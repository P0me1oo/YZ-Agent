# 服务器流量保护

## 仅计费代理流量（v2.17.0）

配套面板 `1.93.0`、管理端 `0.65.0`。保护仍限服务器模式，按同一服务器记录的全部受管节点汇总原始代理上传加下载，不乘倍率，不计系统、其他程序和网卡协议开销。同机中转只计一次，跨服务器入口和落地各记其实际承载；不把中转分项叠加到已包含它的入口总量。

代理累计由面板在接收节点报告时持久化，与报告编号去重共用事务，不依赖用户扣费队列。Node 继续使用已有报告编号和待确认报告文件，失败或重启后重发同一批不会重复计量。首次启用及跨月未拆分的报告按首次成功接收的周期计入；上报间隔内可能超出额度。

新模式不调用网卡读取器，管理端隐藏网卡输入，保留原单向、双向及原网卡设置。两套用量独立保存，切换不换算、不清零；切回网卡继续原基线。代理额度随约五秒一次的管理交换下发，Node 按累计上传加下载判断超限；超过 30 秒未得到面板确认时暂停代理，管理连接保留。新周期或提高额度后沿用重新发现管理员启用节点的恢复流程。

代理累计以面板数据库为准，Node 重启或本地文件丢失后先重新确认，再恢复累计；本地写盘失败仍进入保护，恢复后重试。网卡模式原有文件丢失、读网卡失败和离线本地计量规则不变。额度为 0 时不因计量失败暂停。新心跳携带模式和策略版本，旧来源或旧版本报告不能覆盖切换后的状态。

两个核心及固定依赖不变，无新增数据库迁移。先更新面板，再升级全部 Node，最后选择代理模式；旧 Node 不能确认该模式。详细规则及本地验证见配套面板说明与[兼容矩阵](../YZ_COMPATIBILITY.md)。以下为原网卡模式说明。

Node `v2.11.0` 已发布，配套面板 `1.82.0`。设置、计量口径和恢复规则见[面板使用说明](https://github.com/P0me1oo/YZboard/blob/v1.82.0/docs/server-traffic-protection.md)。先更新面板，再更新全部 Node，最后设置服务器额度。

仅服务器模式启用该功能，保护范围是绑定到同一服务器记录的全部受管节点。采样来自 Linux 外网网卡，与代理统计完全独立；管理通道不被额度门禁关闭。首次启用从 0 开始，不提供校准；已有服务器默认不限。

计量状态和网卡基线保存在实例配置目录，进程重启、接口计数归零和系统重启不会主动清除已用量。面板不可达期间仍按本地策略计量和保护；周期依据随策略下发的面板时区及重置日计算。额度或周期恢复时重新发现管理员启用的节点。

核心包装层增加立即停止能力，额度保护跳过普通停止的五秒排空等待；Xray 同时关闭重载后仍在排空的旧实例，sing-box 立即关闭监听和连接，普通 WireGuard 包装层透传并关闭自身隧道。两个核心 fork 的源码和固定依赖没有修改。

常规升级必须保留实例目录。状态文件丢失且面板曾经接受计量时，暂停至下一周期；无法可靠读取外网网卡或持久化状态时也保持保护。Windows 可进行计量状态机和核心本地回环测试，不提供 Windows 网卡计量。

本地及正式发布验证见 [YZ_COMPATIBILITY.md](../YZ_COMPATIBILITY.md)。尚未进行真实服务器联调；回退旧版本将失去本地流量保护能力。

## 默认出口识别修复（v2.11.1，未发布）

`v2.11.0` 自动选择计费网卡时，只接受目标为空的默认路由；使用的网络库会将其补成 IPv4 `0.0.0.0/0` 或 IPv6 `::/0`，导致正常出口也可能显示“无法识别计费网卡”。`v2.11.1` 同时识别这几种表示，继续按每个地址族的主路由表和最低路由优先级选择出口，再解析底层网卡并去重。

指定计费网卡会绕过默认路由选择，但仍校验网卡及读取权限。修复不需要清空计量文件；已累计的流量继续保留。额度为 0 时，计量错误不会暂停代理；开启额度保护后，无法计量仍按原规则暂停代理。

## LXC 出口计量修复（v2.13.1）

LXC 来宾系统的外网接口通常是 veth，在系统中位于虚拟设备目录。旧版本仅允许硬件出口，导致网卡计数可以正常读取，但仍被上报为“无法识别计费网卡”。

现在允许对端位于其他网络空间、且自身未加入桥接或其他主接口的以太网 veth。自动模式仍选择 IPv4、IPv6 的主路由表默认出口；手动指定网卡使用同一校验。双栈共享同一网卡只计一次，使用不同网卡时分别累计。VLAN、bond 和单出口硬件桥接继续解析底层网卡并去重。

宿主机连接容器的桥接端口、同一网络空间内的 veth 对、回环、隧道及无法确认类型的虚拟设备仍被拒绝；多出口桥接仍需明确指定出口。计量范围是所选接口实际可见的收发字节，不代表虚拟化宿主机的全部流量，也不等同于服务商账单。程序必须能读取所在网络空间对应的系统网卡计数。

升级保留原计量文件。此前一直无法识别出口时，恢复后的首次成功采样建立基线，不补计历史流量；已有累计量不清空。面板接口、计量状态格式、两个核心和异常保护规则不变，无需修改面板。验证范围见[兼容矩阵](../YZ_COMPATIBILITY.md)。

Alpine Linux 同样支持该功能，安装器使用 OpenRC 管理服务；Linux amd64、arm64 程序采用静态构建，不依赖 glibc。网卡仍须符合上述出口条件，且程序能够读取对应计数。
