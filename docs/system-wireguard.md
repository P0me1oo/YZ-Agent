# 系统 TCP WireGuard 中转

`v2.5.0` 在 `v2.0.0` 系统 TCP WG 格式上移除 Xray 本机转接，保留跨核心互通；当前发布状态见 [兼容矩阵](../YZ_COMPATIBILITY.md)。从 WG `1.x` 升级仍需要入口与落地一起更新。

## 数据路径

Linux 上已有 WG 中转配置自动使用新的运行路径，不新增面板开关，也不改变用户订阅。
每条链路建立独立、未命名的网络空间和 TUN 网卡；面板原有重复隧道地址不会进入宿主网络空间。
WireGuard 加密仍由程序内的 wireguard-go 执行，TCP 连接由 Linux 创建，网络空间内要求使用 BBR。
这不是把加密实现切换成 Linux WireGuard 内核模块。

入口通过隧道内的 SOCKS 服务传递目标地址，落地再交给原核心的路由和出站。
sing-box 直接在网络空间创建连接和监听；Xray 现在直接在对应网络空间创建连接和监听，不再启动额外的 sing-box 转接实例或本机转接端口。每条线路继续使用独立网络空间，入口用户管理、限速和计费保持不变。
用户身份、限速、设备限制和计费仍由入口核心执行；原有落地出站与路由继续由所选核心执行。
UDP 使用 SOCKS UDP 转发，不改成 TCP 承载。

## 运行条件与生命周期

- Linux 需要 TUN、BBR、创建网络空间的权限及配置网络接口的权限；缺失时启动报错，不静默退回 Reno。
- 网络空间只通过描述符持有，不挂载到 `/run/netns`，也不修改宿主默认路由或全局 TCP 设置。
- 容器需要显式提供 `/dev/net/tun`、`NET_ADMIN` 和创建网络空间所需的 `SYS_ADMIN` 权限；还需允许相关系统调用和写入网络空间的 TCP 设置。升级镜像本身不会增加这些权限。
- 关闭核心时关闭 WG 入站、设备及网络空间；初始化失败走同一回收路径。配置重载会重建隧道，已有连接可能中断。
- 新版与 `v2.0.0` 以来的隧道格式一致；若 MTU 超过 1420，两端都需升级到支持上限 1500 的版本。不得只把一端回滚到 WG `1.x`。非 Linux 平台仍沿用原核心 WG 实现，不与 Linux 新路径混用。

## v2.5.0 接入约束

Xray 前置复用原 SOCKS 出站，在它创建套接字时锁定线程并进入对应 WG 网络空间。配置只允许固定 IPv4 落地地址，使用普通 TCP/UDP，不启用 TLS、额外中转或多路复用，因此固定核心的拨号路径不会进入域名解析或双栈并行拨号。调用结束恢复原网络空间；恢复失败的线程交给 Go 销毁。更新核心或 Go 时必须重新验证这一约束。

Xray 落地只监听该网络空间的隧道地址，使用 SOCKS 协议库读取目标，再交给当前核心调度器，不启动第二个核心。TCP 握手复用读取缓冲，UDP 保留逐包目标地址和应答包头空间。关闭与创建连接共用运行层锁，防止网络空间描述符关闭后被另一条线路复用。生产代码不保留旧 bridge，测试使用独立对端验证隧道。

面板默认 MTU 1420，可选 1280–1500，已保存的值不覆盖。1500 需要结合底层路径和 WG 封装开销验证，不保证更快。

## 验证状态

已增加 Linux 集成测试，实际创建两端 WG 隧道，读取系统 TCP 套接字的拥塞算法，验证 TCP、UDP 和重复关闭。
2026-10-01 在独立 WSL2 Linux 环境完成历史运行验证（内核 6.18.33.1、Alpine 3.22.2）。2026-10-05 在 YT-HK（Debian 12、Linux 6.1、4 vCPU）重新通过基础隧道测试；DGN-HK（Debian 13、Linux 6.12、2 vCPU）已确认 TUN、BBR 和网络空间权限可用。新直连方案的组合测试、跨机测速和清理结果另行记录，以下清单为此前版本的验收记录。
Linux 集成测试需要上述权限，环境不足会失败，不跳过测试。

- `TestSystemTCPAndUDP`：真实套接字使用 BBR，TCP、UDP 往返及重复关闭通过。
- `TestStartFailureClosesNamespaceAndCanRecover`：转接端口占用时启动失败并关闭网络空间；释放端口后重新创建、启动通过。
- `TestWireGuardRelayRuntime`：最新八组全部通过（263.02 秒），覆盖四种核心组合、两种入口协议、TCP／UDP、重复重载、用户增删、线路切换、固定落地端口下修改 MTU 后重载及落地重启。落地固定端口在启动阶段绑定，入口保留已经分配的随机端口，避免重新分配端口使握手应答丢失。
- `TestWireGuardMultipleLandingsAndTraffic`：两个核心的多落地选择、入口流量记录、sing-box 精确线路流量、落地不重复计费通过。
- 既有 SS／VLESS 中转、重载失败恢复、连接限速更新和设备限制相关回归测试通过；不能据此替代线上故障验证。
- Linux amd64、arm64 完整程序构建通过；正式流水线使用固定提交与固定核心依赖，安装包、镜像及校验值见兼容矩阵。
- mihomo v1.19.31 REALITY 联调通过，分别使用 sing-box 客户端和独立 mihomo 进程验证 TCP、UDP 经 WG 到达指定落地。模拟目标站点复用核心的 REALITY 测试设施，避免普通 HTTPS 测试站点的证书记录长度及后台探测干扰握手。
- DGN-HK（Linux 6.12.48）独立临时测试：上传校验通过，BBR 套接字、TCP／UDP、错误密钥拒绝、启动失败回收与恢复全部通过。未替换或重启已有服务；临时程序、旧测试结果和上传残片已清理。此结果不等于跨服务器速度验证。

测试服务器分工：Lightlayer-US、Isvoro-US 做入口，Sadidc-US 做落地；DGN-HK、YT-HK 使用 mihomo 做客户端。
真实服务器测试使用独立实例、临时密钥和监听端口。跨服务器速度尚未完成对照，本版不承诺具体提速幅度。正式发布必须通过流水线的完整 Linux 竞态测试、安装器检查、双架构构建和镜像版本核对；结果记录在兼容矩阵中。
