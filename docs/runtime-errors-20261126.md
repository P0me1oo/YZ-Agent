# 运行错误修补

维护者：P0me1oo。Agent v2.51.1，基于正式 v2.51.0 独立工作树；发布及升级状态见对应记录。不包含主工作区 Next 开发改动。

## IPv6 能力与防火墙

落地 IPv4 通配监听继续考虑 Go 双栈监听，但执行前通过本线程网络空间的 AF_INET6 socket 创建检查内核能力。只有 EAFNOSUPPORT 或 EPROTONOSUPPORT 才裁去有效计划中的 IPv6 监听、转发和来源集合；没有公网地址、默认路由或 UFW IPV6=no 不作为裁剪依据。权限、资源不足等探测失败保留为错误。IPv6 专用监听不能静默改成 IPv4。

UFW 先记录添加意图再执行命令，以便崩溃恢复；以前失败的 IPv6 意图可能留在状态文件。新版本检查 UFW status、show added 和 user6.rules 的十六进制注释，仅在本实例规则确实不存在时回收归属。如果有持久规则而内核不能执行对应命令，保持归属和待处理提示，不改写管理员规则文件。

内核关闭 IPv6 时 iptables 来源和端口转发不调用不可用的 ip6tables；其他地址族仍按原事务及回读机制核验。系统重新启用 IPv6 后重新生成双栈计划。UFW 的 IPv6 未启用错误使用固定原因，不将完整命令输出或规则注释复制到日志。

## 通信诊断

面板请求包含 16 位十六进制随机关联编号。失败包含当前阶段、总时间、DNS/连接/TLS/请求发出/首字节相对请求起点的时间、连接复用状态；尚未完成阶段为 0，未取得面板耗时为 -1。响应体读取错误同样带诊断。

配套面板 2.30.1 回报请求处理耗时，并为已认证的慢请求或服务端失败记录相同编号。此处只包装返回错误，不主动输出日志或采集请求正文，原调用方的限频、隐私关闭和上传器本地诊断策略继续生效。

## 验证范围

防火墙和面板客户端整包测试及 `go test -race -count=1` 通过；Linux amd64/arm64 按正式功能标签构建通过，核心依赖未变；隔离网络空间的 nftables 与 iptables 双栈来源允许/拒绝/回滚各通过一次。单元测试覆盖不支持 IPv6、未知能力、双栈保留、旧 UFW 意图与持久归属、请求超时和响应体超时。生产仅执行另行授权的依赖安装与启动参数修改，未向生产注入测试故障。构建只用于本地验证，不作为已发布安装包。
