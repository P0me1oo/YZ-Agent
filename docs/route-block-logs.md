# 路由拦截记录

[v2.36.0](https://github.com/P0me1oo/YZ-Agent/releases/tag/v2.36.0) 已正式发布并完成附件下载核验，见[发布记录](release-2.36.0.md)。支持面板 `2.10.0` 起的路由拦截上报；推荐配套已部署的面板 `2.11.0`、管理端 `0.95.0`，在“路由管理 → 拦截记录”按用户查看。发布安装包不会自动升级运行中的节点。

面板声明 `block_log.version=1` 后，Agent 采集面板 `action=block` 规则的实际命中：Xray 在最终黑洞出站分发时采集，sing-box 在选路后的连接追踪器中采集。规则使用独立的 `yz-panel-block-<规则编号>` 标签；保留既有匹配顺序、网络与协议条件，不重新匹配目标或解析运行日志。自定义出站禁止占用该标签前缀，两个核心源码与依赖不变。

记录节点、用户、规则编号、请求时间、目标主机、端口与 TCP/UDP。普通 WireGuard 在已有用户准入层把用户编号经进程内上下文传给核心，不改变认证或流量计数。中转落地使用共享凭据，用户记为 `0`，面板显示“无法识别”；只记录落地实际命中的规则，不从入口请求推测用户。入口自身流量仍按入口用户记录。

独立协程每 5 秒批量上报 `/api/v2/server/block-log`。复用 `internal/accesslog` 的有界队列与持久化机制，增加可选规则编号和网络字段；普通访问记录不发送这些字段，原接口与缓存兼容。拦截使用单独的 `pending-block-*.json`，按面板、机器和节点隔离，沿用隐私存储和 `0600` 权限；固定批次按原编号重试，每批最多 256 条、每节点最多 32,768 条，缓存 7 天过期。满队列、磁盘错误与突然终止不保证全量保存。

重新加载沿用记录器。规则匹配条件变化可以热更新；新增、移除禁止访问规则或切换动作改变原生出站集合，沿用实例重建路径，可能中断现有连接。Agent 面对旧面板或独立运行模式不启用新采集。面板默认记录，不受通用日志开关控制；在“路由管理 → 拦截记录”内设置保存天数。机器隐私保护继续优先，不改变实际拦截行为或原访问记录。

详细字段、用户查询、隐私策略、保留期及回退见[面板说明](../../YZboard/docs/route-block-logs.md)，验证见[兼容矩阵](../YZ_COMPATIBILITY.md)。
