# 超限来源快照

面板 `1.62.0` 与 Node `v2.10.0` 为 Telegram 超限提醒增加 IP 信息，不增加日志查询入口。Node 只提供准入现场数据，IP 归属查询与通知仍由面板负责。

## 上报约定

- 每用户、每类、每周期保留首次记录的一次拒绝快照；原周期次数、并发峰值与设备拒绝地址汇总保持原义。并发和速率独立保存，面板可以在同一条消息展示。
- 可选 `snapshot` 包含 `occurred_at`（Unix 秒）、`limit`、`observed`、`source_ip`、`active_ips`、`active_total`、`active_known`。上限、占用值、来源取同一次事件；已有来源去重、排序后最多五条，总数单独保存。它不是整个周期的全部拒绝来源或发送时在线状态。
- 设备名额由面板协调时，拒绝响应新增同结构 `limit_snapshot`；面板在用户名额锁内生成来源，Node 随拒绝事件带回。旧面板缺少该结构时，只报告被拒来源，占用来源未知。
- 旧设备协议依据有效跨节点快照和本机来源判断；IPv6 已按 `/64` 合并，保留网段标记，不能还原完整地址。现代协调快照保留完整地址，IP 数量可能多于设备名额数。
- 并发与速率来源取本节点的已有连接；普通 WireGuard 随每条连接登记和释放公网来源。速率没有“已占速率名额”的含义，面板展示「已连接的 IP」。Xray 的旧准入流程提前登记新请求，快照扣除本次尚未通过的登记，同地址已有连接继续保留。
- 统计取出后清空，失败上报由原批次重试，不重新采集在线名单。删除用户后迟到事件不会重新创建记录。新结构放在独立传输包，原可选接口和旧插件继续兼容。

## 验证范围

覆盖快照与首次事件一致、周期重置、并发上报、用户删除、两核心 TCP/UDP 拒绝与同地址已有连接、跨节点设备来源、面板拒绝回复传递及普通 WG 关闭释放。正式发布继续执行完整 Linux 竞态检查、现有核心兼容包、Mihomo 联调、安装器、防火墙与双架构构建。
