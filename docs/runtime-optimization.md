# v2.9.0 运行开销优化

配套面板 `1.57.0`，沿用原有两个核心固定依赖，管理端使用 `0.32.0`。发布及完整验证结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)，服务器更新由用户执行。

## 设备同步

主控通过握手分别声明设备长连接和快照续期能力。Node 复用机器现有连接发送设备会话、来源申请和同步；确认必须同时匹配请求编号、节点和操作。断线、发送失败或确认丢失时 HTTP 补发同一运行身份、序号及内容；明确的业务拒绝直接返回，不另发一次申请。

每秒同步保持原目标。第一次、来源变化、待处理申请变化和真实关闭时发送完整快照；完整内容确认后，来源未变化只发送存活续期。来源年龄自然增长不算变化，实际新连接序号参与比较。收到撤销仍调用原连接关闭逻辑，必须等实际释放后才报告来源退出。

续期基线不符时按同一序号补发完整快照，不关闭活跃连接；会话丢失仍按原规则先关闭旧来源再重新握手。旧主控不声明能力时继续完整 HTTP 同步；主控回滚拒绝续期时立即停用此能力。混用旧 Node 时原有名额协调规则保持不变。

## 系统采样与发送

同一进程内的逻辑节点共用最近一秒的系统采样，统一读取 CPU、内存、磁盘、网卡和运行指标。每核结果返回独立副本，防止调用方污染其他节点。无人查看时仍遵守既有按需采样周期，用户流量、连接及来源统计没有合并。

WebSocket 保留单一写入任务。心跳使用独立位置合并，设备会话与申请、主动同步等控制请求优先。普通队列为 64 项、最多 8 MiB，控制队列 16 项、另保留 64 KiB，等待确认最多 512 项；字节上限不包含当前正在写入的单条消息和调用方原始采样。消息入队前编码一次，发送时复用编码结果。

积压超限明确返回失败，由原有设备或流量补偿处理；不返回虚假成功，也不静默清除计费批次。已取消且尚未发送的请求不再进入网络，已经发出的业务仍依靠原序号去重。断线清理队列和等待表，新连接不会延续旧队列。

## 验证与效果

回归验证来源变化、真实关闭、确认丢失、基线补发、旧会话、两种通道一致、旧版兼容、100 个调用共享一次采样、返回值隔离及队列过载。两个核心和普通 WireGuard 继续走原连接生命周期，完整检查与构建记录见兼容矩阵。

这些修改减少 HTTP 和系统读取次数，不承诺固定 CPU 降幅。主控镜像和历史日志占用不会随源码修改自动释放，部署后的占用与日志增长需在同等业务量下重新测量。
