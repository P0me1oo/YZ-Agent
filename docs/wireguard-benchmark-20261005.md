# Xray 直接接入 WG 的跨机验证

日期：2026-10-05。版本：Node `v2.5.0`，面板 `1.46.0`、管理端 `0.23.0`。

## 结论

移除 Xray 本机转接后，四种前置与落地核心组合均通过功能测试。跨机实测约 83–96 Mbps，新旧速度接近，没有足够证据宣称明显提速。新方案的入口测试进程在下载时消耗的 CPU 时间较低；上传结果接近，不能将本次有限样本转换为稳定的节省比例。

默认 MTU 1420 合适。本次路径使用 1500 时，小包和 TCP 握手可以成功，大流量全部超时；1380 与 1420 均正常，未发现 1380 更快。允许上限 1500 不代表所有路径都适用。

## 环境与方法

- 入口 YT-HK：Debian 12、Linux 6.1、4 vCPU、4 GB；落地 DGN-HK：Debian 13、Linux 6.12、2 vCPU、2 GB。两台均为 amd64，物理接口 MTU 1500。
- 路径为测试客户端 → 本机 VLESS 入口 → 跨机 WG → 落地核心 → 本机测试目标；目标仅监听回环地址。使用临时独立密钥、端口及目录。
- 每个 TCP 项目传输总量 128 MiB，分别测下载、上传及 1/4 并发；收到完整应答后才算成功。UDP 每组 100 个 1200 字节包。
- 新测试程序包含提交 `a706a22ca0ffc4ef6268a987718b9f870b7c3c4f` 的运行层修改；旧对照以基线 `5cfdf30a8df939384bc12ff666c1d59a7b2f6e44` 的运行层通过 Go overlay 构建，使用相同测试代码与固定核心依赖。
- 测试工具仅在显式添加 `with_wg_benchmark` 构建标签时启用。新程序 SHA256：`fbb8d2e8002fb3136d752fdcd638468d9f242ccf61d2f26fcf1498d4bdf23315`；旧程序：`73c02d19a57a54b8b8dcc9d3f2d1e7003f8cf782886197925daee52f5eaac498`。两端上传后校验一致，测试程序不是正式 Release 安装包。
- CPU 时间是入口整个测试进程的用户态和内核态时间之和，包含测试客户端、核心和 WG；未测量独立落地 CPU。测试顺序运行，未隔离公网波动，不能证明线路带宽上限或生产性能收益。

## 功能回归与边界

- YT-HK：Xray/sing-box 前置 × Xray/sing-box 落地 × VLESS/HY2 入口，八组通过，289.03 秒。覆盖 TCP/UDP、用户增删、重复重载、停用恢复、固定端口改 MTU 与落地重启。
- 两种前置的多落地隔离与流量统计检查通过，1.53 秒。
- DGN-HK：四项系统 WG 测试通过，覆盖并发网络空间隔离、取消、关闭后拒绝、TCP BBR、UDP、错误密钥及端口占用后的回收和恢复。
- 开发期间发现的核心上下文缺失、UDP 回包头空间、失败连接包装清理问题均已修正，完整组合重新通过。
- 本次跨机速度覆盖 Xray → sing-box、Xray → Xray、sing-box → sing-box；sing-box → Xray 的互通通过功能回归，没有单独测跨机速度。
- ARM64 由正式流水线构建和执行镜像版本检查，未在 ARM64 真实服务器测试 WG。安装包、正式 Linux 竞态回归及镜像证据见 [兼容矩阵](../YZ_COMPATIBILITY.md)。
