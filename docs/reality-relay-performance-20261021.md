# YZ-Agent 三机中转性能实测

日期：2026-10-21。维护者：P0me1oo。目标版本：v2.23.0，未提交、未发布。

结论：本次没有测出新 shortId 入口稳定的速度优势。splice 比同入口的 buffered 和现有链式入口少用前置 CPU，但 Realm 的前置 CPU、内存和短连接耗时更低。暂不正式集成，保留实验入口；计费、设备数及真实来源地址仍未接入，不能把这些结果用于生产升级。

后续 [Elise SS2022 落地补测](elise-ss2022-performance-20261021.md) 已将落地代理与 HTTPS 目标拆成独立进程，比较相同链路下的 Go/Rust 落地。该补测是独立系列，本报告的合并落地 CPU 数据保留原含义。

## 来源和方法

- 所有 Go 方案、落地和客户端使用同一测试程序：Go 1.27.0、Linux amd64、CGO 关闭、单核执行、192MiB Go 内存软上限；程序复用项目真实 sing-box 包装器及新中转模块。固定核心为 `github.com/P0me1oo/YZ-sing-box v1.15.0`。构建来源 revision 为上述基线，`vcs.modified=true`。
- 测试程序 SHA-256：`90111a1094252df10b4b63f24bc913d0f7303c1eb1a2466435819ec6a020703e`，三台上传后分别核验一致。
- Realm 使用 v2.9.6 官方 Linux x86_64 musl 程序，固定源码 `7e9f44c4b6414079fdd7ed27eea155066df80dd9`，SHA-256 `6a1733bfc51e3d19743757ca08f4c81f36afe7972eab0607bef264fc99064208`。它使用 Rust 官方构建，不与 Go 使用同一编译器。

- 相同客户端身份、Reality/Vision TCP、SNI `relay-perf.test`、前置端口 28101、HTTPS HTTP/1.1 数据目标；测试端口 28102–28106，HTTPS 仅监听落地回环地址。落地每次只启动当前方案的核心。

- 用户取消总流量限制后，重新执行完整五组、三次交错对照。每组上传和下载分别为单连接 512MiB、四并发合计 512MiB、128 个新连接合计 8MiB。大载荷每项持续约 4.5–6.1 秒，每组大载荷合计 2GiB。最终系列总量 30.23GiB，连同此前请求累计预留约 32.98GiB；这是请求预算，包含失败项，不是确认有效载荷或服务器账单流量。
- 第一轮顺序为新 splice、旧 SS2022、Realm、旧 VLESS、新 buffered；第二轮反向；第三轮为 Realm、新 splice、旧 VLESS、新 buffered、旧 SS2022。每项间隔一秒，进程在组间重启。最终系列 90 项、3990 个请求全部成功。
- 下载仅累计完整收到的载荷；上传仅累计服务端确认实际收到的载荷。关闭连接复用，每个请求均建立新连接；单连接大载荷用于观察持续传输，短请求用于观察建立和结束连接的开销。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 新 shortId splice | 903 | 920 | 936 | 909 | 39 | 29 |
| 新 shortId buffered | 922 | 910 | 933 | 880 | 38 | 28 |
| Realm TCP 透传 | 929 | 913 | 940 | 925 | 43 | 31 |
| sing-box → SS2022 | 892 | 928 | 932 | 909 | 40 | 29 |

单连接上传三轮范围：新 splice 902–923、buffered 909–923、Realm 706–931、旧 SS2022 715–923、旧 VLESS 930–934Mbps。buffered 单连接下载有一次约 709Mbps，其余两轮约 910–930Mbps。低速没有只出现在某一个方案，不能用单次结果断言转发器上限。

## 三台 CPU 和内存

CPU 时间是程序实际占用 CPU 的累计秒数，越少表示完成相同载荷所需 CPU 越少。下表取每轮四项大载荷合计 2GiB 的累计值，再取三轮中位数；内存为该系列大载荷期间观察到的峰值常驻内存，单位 MiB。

| 方案 | 前置 CPU 秒 | 落地 CPU 秒 | 客户端 CPU 秒 | 前置内存 | 落地内存 | 客户端内存 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 新 shortId splice | 3.85 | 8.92 | 10.92 | 29.1 | 45.6 | 41.8 |
| 新 shortId buffered | 4.55 | 7.97 | 11.14 | 29.3 | 45.3 | 41.8 |
| Realm TCP 透传 | 2.46 | 8.86 | 11.05 | 3.2 | 43.7 | 41.8 |
| sing-box → SS2022 | 5.21 | 9.41 | 10.22 | 41.3 | 42.5 | 41.3 |
| sing-box → VLESS/Reality/Vision | 4.45 | 8.76 | 10.82 | 41.1 | 42.4 | 41.7 |

在本环境下，新 splice 的前置 CPU 时间比 buffered 少约 15%，比旧 SS2022 少约 26%，比旧 VLESS 少约 13%；Realm 比新 splice 少约 36%。这些比例仅对应相同 2GiB 载荷的三轮中位数，不代表最大吞吐提升比例。

四并发时单核 CPU 占用中位数如下，上传/下载分别列出。100% 表示用满一颗 CPU 核心。

| 方案 | 前置 CPU % 上传/下载 | 落地 CPU % 上传/下载 | 客户端 CPU % 上传/下载 |
| --- | ---: | ---: | ---: |
| 新 shortId splice | 19.9 / 22.7 | 65.8 / 32.7 | 47.7 / 70.1 |
| 新 shortId buffered | 24.2 / 27.5 | 54.9 / 31.2 | 46.6 / 67.4 |
| Realm TCP 透传 | 13.6 / 16.0 | 66.5 / 32.2 | 48.2 / 73.8 |
| sing-box → SS2022 | 28.3 / 30.3 | 64.2 / 39.6 | 47.1 / 58.3 |
| sing-box → VLESS/Reality/Vision | 24.4 / 26.5 | 64.9 / 32.9 | 48.5 / 66.5 |

前置与落地每 0.2 秒读取 `/proc` 累计 CPU 计数、RSS 和主机争用，按客户端测量开始和结束时间插值；前置、落地不包含启动 CPU，客户端由 `wait4` 取得逐进程 CPU 和最大 RSS，包含启动和退出。短时采样存在边界误差，不能把小数位当作精确硬件计量。

以下取每轮 128 个 64KiB 新连接请求的中位数，再取三轮中位数，单位毫秒。建立连接耗时包括 Reality、代理及目标 HTTPS 握手；不是前置单独增加的延迟。

| 方案 | 建立连接 上传/下载 | 完整请求 上传/下载 |
| --- | ---: | ---: |
| 新 shortId splice | 9.90 / 9.92 | 12.87 / 17.72 |
| 新 shortId buffered | 9.74 / 10.05 | 12.77 / 17.89 |
| Realm TCP 透传 | 8.64 / 8.85 | 11.68 / 16.65 |
| sing-box → SS2022 | 9.03 / 9.07 | 12.21 / 17.74 |
| sing-box → VLESS/Reality/Vision | 11.94 / 12.05 | 15.16 / 19.89 |

建立连接的 95 分位数（三轮各自 95 分位再取中位数）：新 splice 12.45 / 12.43ms、buffered 13.32 / 12.50ms、Realm 11.23 / 11.00ms、旧 SS2022 12.19 / 11.02ms、旧 VLESS 15.40 / 14.85ms，仍按上传/下载顺序。

最终系列每组 798 个请求全部成功。早期小载荷系列旧 VLESS 有一次下载不完整：128 个请求中 1 个失败，仅完整收到 127 个请求的 8,323,072 字节；该项保留为失败，不纳入速度中位数。工具未保存错误详情，不能确认这次失败发生在链式转发、目标或网络哪一环，也不能据此归因到方案。

## 瓶颈和适用限制

实测前置没有持续接近单核上限；大载荷多在 900–940Mbps，说明这些方案在当前线路上都能达到相近有效速度。推测线路限制了多数结果，但没有独立链路容量基准，不能把相似速度解释为转发能力相同。

上传的落地 CPU 较高，四并发约 55–67%，同一落地还承担 HTTPS 数据目标和握手目标。下载的客户端 CPU 较高，四并发约 58–74%。落地主机 steal（虚拟机被宿主抢走的 CPU 时间）中位数约 1.17%，峰值约 16.10%；上传四并发多为 11–16%。前置峰值约 0.58%，客户端约 0.54%。落地存在少量既有换页活动，期间累计约 164 页进出，不能归因于某个测试进程。

因此不能声称已经测到前置的最大吞吐，也不能排除客户端、落地和宿主争用先限制速度。三台同地区单核虚拟机、一个落地、一条短延迟线路、有限并发和仅三轮不覆盖长距离、丢包、高并发或长时间稳定性。

本次没有在服务器采集 splice 系统调用；实际 splice 证据仍来自此前 Linux 原型验证。不能把启用 splice 的配置等同于逐条远程连接都使用 splice。新入口额外校验 Reality 握手并恢复 shortId，Realm 只做固定 TCP 透传；它们功能边界不同。此处没有多线路选路性能、计费、设备数、来源透传或生产全功能 Agent 对照。
