# 实时配置误重载与长连接断开

## 现象与依据

2026-10-01 排查两台已升级节点：落地运行 `v1.25.1`，前置运行 `v1.26.1`。服务器时间 01:00—02:00，两台机器分别出现 24 次 `xray: configuration changed, performing full restart`，但 systemd 自动重启次数为零。检查只读取版本、进程状态和日志，没有变更服务器配置或服务。

这解释了短请求、延迟探测仍正常而长连接不稳定的现象：新连接可以连接到新核心；旧 Xray 实例在重载后最多保留五分钟，到期关闭仍未结束的连接。日志与代码能确定存在误重载故障，尚未用修复后的生产程序重新验证实际 SSH 会话。

## 根因与版本范围

HTTP 路径把缺省路由、自定义出站、自定义规则转换为明确的空列表。机器共享连接通过 `internal/controlplane/mailbox.go` 复制配置时，使用向 nil 切片追加元素的方式，使这三个空列表变为 nil。配置序列化分别得到 `[]` 和 `null`，服务层与核心层都将其判定为配置变化。

空列表复制问题原先就存在。`v1.25.1` 纳入完整实时快照后，面板每五分钟的用户同步也会携带配置；节点定时 HTTP 对账再应用另一种表示。两种内容相同、表示不同的配置交替触发重载。已发布 `v1.25.1`、`v1.26.1` 均受影响，主要涉及机器模式；是否使用 WG 与故障无关，客户端换成 sing-box 或 Mihomo 也不能解决服务端误重载。

## 修复与验证

`v1.26.2` 只调整三处配置列表复制，保留原来的 nil／空列表状态，不改变真实配置变化、用户限制、流量统计、协议或核心固定依赖。

回归测试通过真实的机器消息缓存和服务同步处理流程交替发送相同配置，并检查实际重载调用次数。修复前，三轮同步触发六次重载；修复后必须为零。同时检查实际修改端口只触发一次重载，随后同步同一配置不再重载；另检查缺省列表和明确空列表经过消息缓存后的序列化保持一致。

最终验证与发布信息见 [兼容矩阵](../YZ_COMPATIBILITY.md)。前置和落地均应更新，核心随 Node 交付，无需单独更新面板或客户端。
