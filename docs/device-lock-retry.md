# 设备锁竞争恢复

维护者：P0me1oo。日期：2026-11-13。Agent v2.37.1，配套面板 2.16.6；本地未发布、未部署。

设备会话、准入和同步请求新增 `lock_retry=1` 声明。面板收到后允许该次协调在锁占用时立即返回 503，避免在同步工作进程中持有节点锁等待其他账号或队列锁。旧面板忽略该字段，保留原锁处理。

收到 503 后，Agent 以 100、200、400、800 毫秒为退避基数，叠加 0–99 毫秒随机等待。基数上限为 800 毫秒，一次调用最多八秒，原调用方更早的截止时间仍优先。等待可由取消信号立即中止，不创建后台重试任务。

重试沿用原业务序号、快照、机器与节点鉴权。WebSocket 的每次传输仍使用独立请求编号，只接受对应节点、操作和请求的确认；锁占用不隔离正常长连接，也不额外触发 HTTP 补偿。原有丢失确认后的跨通道补偿继续使用同一业务内容。

503 不是许可或同步成功。403、409、412、500 及其他错误不进入本次新增退避，保留原会话失效、完整快照和拒绝处理。流量批次、核心、出站策略和设备名额规则没有修改。

面板端测试覆盖真实 Redis 锁竞争、部分状态已写入后的同序号恢复、权限撤销及重复归还，见[配套面板说明](../../YZboard/docs/runtime-log-fixes-20261113.md)。Agent 测试使用 Go 1.27.3，并对面板客户端和设备协调包执行 `go test -mod=readonly -race -count=1`，覆盖 HTTP / WebSocket 503 后恢复、原始内容保留、取消和非 503 拒绝。
