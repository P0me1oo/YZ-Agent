# REALITY shortId 中转实验

实验最初在 `feat/reality-shortid-relay` 分支、基线 `c7d1fed7582578fad82851449c9a77e4d42daaf1` 上开发，以 `v2.23.0` 原型完成性能比较；审查修复纳入 `v2.24.0` 开发版本，尚未发布。实验命令尚未通过面板下发，不修改原有实例和自动防火墙；两个核心源码及固定依赖保持原版本。历史性能报告继续保留当时的版本和构建来源。

## 数据路径

客户端连接同一个入口地址、TCP 端口及 SNI，通过不同 shortId 选择落地。前置收齐 ClientHello，在副本上使用对应 Reality 私钥执行 X25519、HKDF-SHA256 和 AES-GCM 认证，恢复客户端时间及 shortId，再将原始握手逐字节送给固定目标。后续 Reality/TLS 和 VLESS 连接由客户端与落地完成，前置不解析用户 UUID 或访问目标，不生成第二段内部代理或重新加密载荷。

落地必须提供实际面对客户端的 Reality/VLESS 入站，并配置匹配的 Reality 密钥、shortId 和用户身份；已有只接受内部凭据的中转落地不能直接代替它。实现参考 Realm 普通 TCP 的双向零拷贝思路，没有引入 Realm 程序或 Rust 运行依赖。

## 配置及启动

使用 `yz-agent experiment reality-relay --config PATH` 显式启动，附加 `--check` 时只校验配置。以下仅说明格式，占位内容必须由本次隔离测试临时生成，不能直接运行：

```yaml
listen: 127.0.0.1:8443
server_names: [reality.test]
keys:
  - name: shared
    private_key_env: YZ_RELAY_TEST_PRIVATE_KEY
routes:
  - name: first
    key: shared
    short_id: "<本次生成的线路一标识>"
    target: "<本次确认的落地一地址>:443"
  - name: second
    key: shared
    short_id: "<本次生成的线路二标识>"
    target: "<本次确认的落地二地址>:443"
copy_mode: auto
handshake_timeout: 5s
dial_timeout: 5s
max_time_diff: 2m
max_connections: 4096
max_handshakes: 256
```

- `listen` 为 IP 和端口；端口 0 用于本地动态分配。测试 443 前须确认该测试地址端口空闲，避免占用现有服务。
- 每组密钥只能引用 `private_key_env` 或 `private_key_file` 之一，不支持在 YAML 中直接填写私钥。私钥为 X25519 URL-safe Base64；Linux 私钥文件必须为普通文件且只允许所有者访问，命名管道等特殊文件会直接拒绝，不等待写入端。
- 最多 32 组不同认证密钥，前置逐组尝试。共享一组 Reality 密钥、为线路分配不同 shortId 可减少首包认证开销。前置因此进入对应私钥的信任范围。
- shortId 为 2–16 位偶数长度十六进制文本，右侧补零到 8 字节。同组密钥中的标识必须唯一，不接受空标识。
- 服务名须明确列入名单，不支持通配符或根据客户端输入决定拨号目标。支持传统 X25519 与 X25519MLKEM768 中的 X25519 部分；同时出现时优先采用独立 X25519，与固定核心的兼容逻辑一致。
- 默认拒绝未认证、过期或未知线路。可显式配置固定 `fallback`，使服务名合法但认证失败的完整握手转到该目标；格式错误或不在名单的 SNI 仍关闭。这不等于已复现正式 Reality 的所有伪装行为。
- 默认每 10 秒输出 JSON 统计，`--stats-interval` 可调整。只输出线路名称、连接数、结束连接的原始字节数和错误数，不输出密钥、shortId、用户身份或完整配置。

## 零拷贝和对照

- `auto`：Linux 使用两端原始 TCPConn 的标准库优化路径，其他系统使用缓冲复制。
- `splice`：要求 Linux，选择同一原始 TCP 路径。标准库在内核拒绝优化时仍可能回退，不能仅凭配置或 `splice_capable` 统计声称实际发生零拷贝。
- `buffered`：显式屏蔽 ReaderFrom/WriterTo，使用 32 KiB 用户态缓冲，供同一程序、同一路线对照。

开头握手读取、认证及发送仍需少量用户态处理。后续是否实际使用 splice，应通过只观察 `splice` 的 Linux 系统调用统计确认，不跟踪 read/write 内容或采集握手载荷。线路流量包含 TLS/VLESS 封装，在连接结束时结算，不能直接当成用户账单。

## 生命周期及限制

- 每秒检查指定配置文件的修改时间。重载失败保留旧配置，并按 1 至 30 秒退避重试同一版本；相同版本的重复错误只报告一次，新版本不受旧版本退避影响。配置或依赖暂时无法读取后恢复，无需再次改写配置文件。相同配置不打断连接；有效配置变化会关闭全部旧连接，重连后使用新映射。监听地址和并发容量变化需要重启实验命令。
- 修改私钥文件后，需更新配置文件修改时间或重新启动，使密钥重新加载；修改环境变量中的密钥需要重启实验进程。两端和客户端须使用正常系统时间。
- 支持 TCP 半关闭。停止入口会关闭本次入口持有的监听和连接；前台命令不安装服务、不自动开启防火墙或接管原有实例。
- 接收新连接遇到暂时资源不足时，在 5 毫秒至 1 秒之间退避重试，保留存量连接；停止信号可立即中断等待，资源恢复后继续接收。
- 只监听 TCP。VLESS 内承载的 UDP 可以随 TCP 连接透传，不增加独立 UDP 转发口；原生 HY2/QUIC 不属于本实验。
- 用户身份、权限及限速由落地验证。尚未接入面板计费归属，未发送 PROXY 头，落地看到前置地址，设备数和来源策略不能直接套用现有生产规则。
- shortId 认证不能识别具体用户，也不代表客户端拥有落地的 VLESS 用户权限。密钥内容不进入校验错误、统计和连接日志。

## 验证与真实服务器比较

本地专项覆盖握手分片、传统/混合密钥、原始握手保留、认证错误、时间窗口、配置错误及敏感信息遮蔽、TCP 半关闭、重载失败/重复/恢复、停止和双核心真实客户端联通。实际执行结果记录在兼容矩阵，不用计划代替通过结果。

经用户授权，三台独立服务器的五组对照已完成，速度、三台 CPU、内存、连接开销和限制见 [实测报告](reality-relay-performance-20261021.md)。新 splice 比 buffered 少用一些前置 CPU，但没有稳定速度优势，Realm 的前置资源和短连接耗时更低。审查修复后保留独立实验入口纳入开发版本，不默认启用或接入面板。

比较现有 Reality 链式中转、实验 splice、实验 buffered 三组；优先使用同一份实验程序分别启动原链路和两种实验模式，使 Go 版本、构建参数及内嵌核心一致。固定硬件、线路、目标、数据量及并发，分别测长连接吞吐和大量短连接。记录成功传完的有效数据、前置及落地 CPU 时间、常驻内存、失败/重传和实际 splice 调用；多轮交错执行，不预设提速或节省比例。

使用临时密钥、用户和独立监听，不使用生产身份。本次经用户明确授权，仅通过 netcatty MCP 代执行限定范围的隔离操作；两条来源受限的临时防火墙规则另行获准。测试结束已停止程序、撤销规则、删除三台隔离目录及临时身份，仅在本地保留程序和脱敏测量。本分支不提供生产升级命令，也不代表已发布或部署。
