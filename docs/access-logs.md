# 代理访问记录

Node `v2.13.0` 配套面板 `1.86.0`、管理端 `0.58.0`，当前为本地开发版本，尚未发布。两个核心保持既有固定依赖，不修改核心源码。

面板握手声明 `access_log.version=1` 后，Node 开始采集通过用户准入的目标请求。Xray、sing-box 在 Node 的核心适配层取得信息；普通 WireGuard 在 Node 管理的用户连接入口取得身份。重载沿用相同记录器，中转落地不重复采集。

仅上报用户编号、连接 Unix 秒、目标主机和端口。域名优先，不能识别则使用 IP；不为此新增嗅探、DNS 反查、解密或内容采集。TCP 记录逻辑连接，UDP 记录目标会话，记录并不代表网页访问成功。

独立协程每 5 秒向 `/api/v2/server/access-log` 发送批次，每批最多 256 条。每节点队列上限 32,768 条。发送前一次保存固定批次快照，按原编号重试，确认后删除已发送部分；配置目录中的 `pending-access-*.json` 按面板、机器、节点身份隔离，以 `0600` 权限保存。不把记录写入流量结算文件，也不影响流量余额。

过期批次按 7×24 小时排除，停用节点的磁盘缓存到下次启动时再处理。正常退出保存剩余队列；强制终止可能丢失上次快照后的记录。磁盘失败或长时间离线可能造成队列满，满时丢弃新记录并只记录数量。损坏缓存不覆盖，本次运行停止采集并记录错误。需要持续、完整审计的场景不能将此功能视作无损日志系统。

旧面板不声明能力时不新增采集，也不会向不存在的接口发送请求。旧 Node 升级前的连接不能补录。独立运行模式不采集。面板字段、查询、清理和回退规则见[面板访问记录说明](../../YZboard/docs/access-logs.md)。
