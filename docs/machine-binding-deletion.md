# 已删除服务器的自动解绑

YZ-Agent v2.57.0 配套 YZboard 2.32.0、YZboard-Next 0.39.0。管理员删除服务器后，在线 Agent 收到定向长连接通知便发起一次控制心跳。仅使用 HTTP 时，下一次常规心跳即可完成确认。离线 Agent 在恢复连接后核实持久删除记录。

## Agent 如何核实删除

机器控制心跳 `POST /api/v2/server/machine/control` 携带 32 字节的随机挑战 `nonce`，编码为 64 个小写十六进制字符。`machine.deleted` 长连接事件只唤醒对应机器的心跳，同一连接重复提示只唤醒一次。正常运行期间已经移除每 30 秒的独立状态查询。启动或安装合并需要检查旧配置时，以及文件保护暂时阻止机器运行时，可在节点发现请求 `POST /api/v2/server/machine/nodes` 中使用相同协议。

面板把删除记录与实际删除放在同一事务，保存机器编号、删除时间及原令牌摘要。匹配的请求收到 HTTP 200，`binding_deletion` 包含版本 `1`、状态 `deleted`、原机器编号、本次挑战和十六进制签名。双方以原令牌的二进制 SHA-256 摘要为密钥，对 `yz-agent-machine-deleted-v1\n<十进制机器编号>\n<挑战>` 计算 HMAC-SHA256。每个 `\n` 为一个换行。Agent 仅接受配置的 HTTPS 面板或本机回环 HTTP 返回的直接确认。

## 本地清理

Agent 再次核对配置文件与凭据，只移除与确认匹配的面板、机器及凭据对应的实例，清理其安装摘要和独占凭据。共用凭据、证书、待补报流量及历史备份保留。本地完成记录用于恢复部分写入，运行中的配置通过原有重载流程生效。最后一个绑定移除后，进程等待新绑定，已配置的健康端口返回 HTTP 503 和 `unbound`。

按实例加密的配置可以使用外层身份核实删除。旧式整文件加密恢复副本需手动处理。

## 新旧版本混用

- 新 Agent 与旧面板仍可运行。旧面板忽略心跳中的挑战，Agent 保留绑定。
- 旧 Agent 与新版面板仍可运行。旧的独立确认接口已移除，旧 Agent 无法自动解绑，升级后可通过持久删除记录补做。
- 令牌轮换、停用、断网、普通 401／403／404／410 和无效或重放的签名都会保留绑定。面板没有保存删除记录的历史身份需要手动处理。
