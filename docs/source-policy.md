# 来源 IP 黑白名单

正式版 `v2.22.0` 配合面板 `1.101.0`、管理端 `0.72.0` 增加节点级自动防火墙开关。开启时先核验系统来源过滤，再确认核心监听并优先放行该节点端口，名单以面板为准；关闭后撤回系统规则，恢复原手工限制，名单仍保留在核心中执行，但不再保证握手前过滤。具体接管、退出、升级及回退条件见[防火墙说明](firewall-port-hopping.md)，发布核验见[兼容记录](../YZ_COMPATIBILITY.md)。

Agent `v2.21.0` 开发版本将来源限制接入系统防火墙，沿用面板 `1.99.0`、管理端 `0.70.0` 的名单和接口；尚未发布。`v2.20.0` 只有核心路由限制，不能阻止 SOCKS5 协商。使用方式见[面板说明](../../YZboard/docs/source-policy.md)，验证结果见[兼容矩阵](../YZ_COMPATIBILITY.md)。

## 配置与兼容

面板按节点下发来源策略（协议字段 `source_policy`）：

| 配置 | 字段 | 含义 |
| --- | --- | --- |
| 限制模式 | `mode` | `disabled` 关闭、`blacklist` 黑名单、`whitelist` 白名单 |
| 大陆屏蔽 | `block_cn` | 仅黑名单或旧大陆策略参与匹配 |
| 允许来源 | `allow_ips` | 白名单的允许地址，或大陆屏蔽的具体例外 |
| 屏蔽来源 | `block_ips` | 黑名单的具体屏蔽地址 |

模式缺失时保留历史行为：大陆屏蔽开启才启用策略。明确关闭优先于保留的大陆开关及名单。白名单至少填写一个地址，每份名单至多 128 个具体 IPv4/IPv6，不接受域名、网段、带区域的 IPv6、未指定地址、组播地址或等价重复地址。

白名单从全部 IPv4/IPv6 地址中扣除允许地址，生成统一的拦截集合，不受保留的大陆开关或具体黑名单影响。黑名单先从大陆集合中扣除允许例外，再加入具体黑名单，因此具体黑名单优先于地区例外。手动名单不读取、下载或刷新大陆库。

Node 深拷贝名单进入配置快照，原始策略参与配置去重，编译后的集合另参与核心重载判断。受保护节点的模式、名单、地区集合或其他运行配置变化时，先停止旧监听，再安装规则并重新启动；已有连接会中断。

## 执行范围

Xray、sing-box 和普通 WG 在固定监听端口接入同一套系统防火墙来源集合。规则先写入并回读核验，再启动监听；白名单外或黑名单内来源在 SOCKS5、TLS 等协议握手前丢弃。过滤精确匹配监听地址、协议和端口，不修改系统默认策略或 SSH 等其他端口。已有公开放行不能绕过来源丢弃。受保护端口的 REALITY 伪装回源也受系统来源限制。

核心原有来源路由和普通 WG 外层检查继续保留，通过防火墙的连接仍需通过认证、权限和后续路由。接收 PROXY 协议时，防火墙按数据包的上一跳 IP 判断，核心仍按解析后的来源判断；白名单需同时包含可信上一跳和允许客户端，或在前置节点执行用户来源限制。Node 不自动猜测、豁免或信任上一跳。

Linux 必须有可管理的过滤后端。自动选择时，运行中的 UFW 配合完整的 iptables/ip6tables、restore 和 ipset 工具使用；否则优先 nft，再尝试上述 iptables 组合。UFW 与 firewalld 同时运行时报告冲突。可通过 `firewall.source_backend` 指定 `nftables` 或 `iptables`，已有归属记录在清理前继续使用原后端。程序不自动安装工具、开启防火墙服务或切换系统后端。

nftables 使用独立的 `inet yz_source_<实例标识>` 表及内置区间集合；iptables 使用 `mangle/INPUT` 中的独立链和 ipset，先于 UFW 的普通放行执行。更新使用 nft 事务、iptables-restore 及 ipset 交换，核验实际地址集合和规则。仅修改本实例归属的对象，冲突或非托管引用均报错。包含来源过滤的归属状态使用版本 3，完全清理后恢复可供旧版读取的状态版本。

开启来源限制后，关闭防火墙管理、非 Linux、缺少工具、无权限、规则冲突、写入或回读失败均停止该节点；落地节点同样执行，不沿用普通端口放行失败时的保留监听逻辑。运行中按流量采样周期检查，最短间隔 5 秒；发现异常且无法恢复则停止。每 30 秒尝试恢复因来源防火墙故障停止的节点，规则重新核验后才启动；不会绕过证书等其他配置错误。外部任意清空或改写规则到下一次检测之间仍有窗口，不能视为持续防篡改保证。

普通 WG 在外层 UDP 接收和发送处匹配同一集合；WG 中转落地拒绝单独启用来源限制，应在前置入口设置。普通代理入口和非 WG 落地分别执行本节点策略，不自动识别或放行前置出口。sing-box SOCKS 动态 UDP 会话端口、自定义额外入站不在固定端口托管范围内；SOCKS 的控制连接先经过系统来源限制，动态 UDP 继续沿用核心准入和路由检查。容器需要对应网络空间的管理权限，宿主机 DNAT 转发到普通容器的流量不属于容器内自动托管保证。

## 大陆库缓存与故障处理

仅启用大陆屏蔽时使用 `https://raw.githubusercontent.com/Loyalsoldier/geoip/release/text/cn.txt`，两种核心共用。有效数据保存为地理数据目录中的 `cn-source.txt`，同目录共用下载锁与不可变内存快照。

每 24 小时刷新，失败 5 分钟退避，运行循环每分钟检查。HTTPS 下载限制 20 秒、4 MiB，数据须同时包含 IPv4 和 IPv6，不接受空库、错误页面、无效条目或全地址网段。先校验并写入临时文件，再替换有效缓存；顺序、空白或重复条目变化不产生新版本。

更新失败保留旧数据；首次没有有效库时停止该节点，后台取得数据后恢复，不降级为无限制运行。重启复用有效缓存。切到手动名单后，迟到的地区下载结果不触发该节点重载。

## 验证与回退

测试只使用保留地址和本机回环来源。专项验证结果记录在兼容矩阵，不将本地模拟接口等同于真实服务器联调。核心 fork 和固定依赖保持不变。

部署需先升级配套 Agent，再启用来源限制；旧 Agent 不提供系统过滤保证。回退旧面板或旧 Agent 前先在面板关闭来源限制、正常停止新版并确认归属规则清理成功。未清理的版本 3 状态不交给旧程序处理。
