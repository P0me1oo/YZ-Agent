# YZ-Agent 审查报告复核与修复方案

核对日期：2026-11-18。维护者：P0me1oo。

核对对象为外部提供的 `yz_agent_audit_report.md`，逐项沿用原报告编号。原报告中未编号的中、低危项在本文分别编号为 M1–M11、L1–L3。

## 核对范围与结论

源码基线为 `3ad2ba4a260aae1f6cfba003589f22d8f31c2e44`，程序版本为 `v2.40.1`，本机使用 Go 1.27.3、Linux amd64。实际核心依赖为 YZ-sing-box `v1.16.0`、YZ-Xray-core `36f4516090e3`，均按当前 `go.mod` 的固定来源核对，没有用旁边核心仓库的移动分支代替。

原报告有参考价值，但不能沿用“25 项全部真实漏洞，4 项严重”的总判断。按每个编号的主要因果链分类，13 项主要结论成立，12 项部分成立或需要修正。一个编号包含多个子问题，因此这个数量不是独立漏洞数量，也不是已发生生产故障的数量。

“成立”表示存在对应实现缺陷，不代表接受原严重程度；“部分成立”表示该编号存在问题，但至少一个重要影响、触发条件或修复建议不准确。没有访问或更新生产服务器，没有验证生产是否已发生这些故障。

重点结果如下：

- **C4 流量恢复缺陷真实且已复现**：确认清空后再产生的流量，进程重新读取时恢复为零。应优先修复。
- **C1 升级校验缺陷真实**：无校验清单仍会执行下载文件；第三方镜像同时提供文件和清单，哈希不能证明发布者身份。
- **H4 的 Xray SOCKS 域名绕过真实且已复现**：没有自定义放行规则时，认证用户通过 `localhost` 到达宿主机回环服务。
- **C3 的核心“僵尸主线程 → 文件描述符失效 → WG 永久断流”因果链不成立**：当前 Go 对初始线程有保留分支。实测网络空间切换后文件描述符仍可打开；真实问题是网卡监控可能读取错误网络空间。
- **M10、L3 的部分结论已有上游保护**：默认服务配置总是重启；正常配置加载会校验负数和异常重连间隔。

## 一、原报告严重项

| 编号 | 核对结果 | 证据与实际影响 | 推荐修复 |
| --- | --- | --- | --- |
| C1 | 成立；安全优先 | [升级事务](/root/YZboard/YZ-Agent/internal/agentcli/upgrade.go:49)识别清单不可达后跳过哈希，随后执行下载程序。[安装器](/root/YZboard/YZ-Agent/install.sh:1279)也有同样回退。没有发布清单签名验证。镜像被控制时，文件和哈希可一起被替换。 | 保留镜像回退，先验证内置公钥对应的签名清单，再验证附件哈希。缺少或无效签名/清单默认终止。历史兼容只能由本机显式选项启用，不能让面板自动升级静默放宽。 |

| C3 | 部分成立；永久断流因果链误报 | [隧道创建](/root/YZboard/YZ-Agent/internal/systemwg/tunnel_linux.go:118)确实锁定线程后不解锁退出，但 [Go 运行时](/root/sdk/go1.27.3/src/runtime/proc.go:1999)对初始线程执行保留等待。临时进程在初始线程切换网络空间后走同一退出路径，`/proc/self/fd`、`/proc/net/dev` 均仍可读取。[网速监控](/root/YZboard/YZ-Agent/internal/monitor/monitor.go:68)使用的 `/proc/net/dev` 会指向初始线程的网络空间，实测只看到隔离空间的 `lo`，当前宿主线程路径仍能看到 `eth0`。 | 把修复目标改为保持宿主网络空间和监控归属。在 Linux 初始化阶段固定初始线程，避免它被用于一次性空间切换；或保存宿主空间句柄，在固定线程内进入该空间读取监控。不要仅替换描述符路径就宣称修复 WG 断流。当前单纯把 fd 路径改为 `/proc/thread-self/fd` 属于加固。 |
| C4 | 成立；计费可靠性优先 | [保存方法](/root/YZboard/YZ-Agent/internal/service/pending_report.go:113)清空时删除检查点和增量目录，但末尾仍记录已保存。[恢复方法](/root/YZboard/YZ-Agent/internal/service/pending_report.go:203)见检查点不存在便直接返回，遗漏后来独立生成的增量文件。正常退出会压缩检查点，崩溃/强杀期间才暴露丢失。 | 清空成功后重置“已有检查点”标记、比较基线和哈希状态，使下一笔非空状态先完整落盘。同时处理已经存在的孤立增量目录：识别、恢复或隔离保留，不能继续直接删除。 |

C3 的主线程保留行为与 [Go 官方运行时源码](https://go.dev/src/runtime/proc.go)一致。这里核对的是当前固定 Go 版本；没有证据支持报告所称的主线程变为僵尸及描述符持续返回文件不存在。

C4 原报告“最多 126 轮、约 21 分钟”需要改为：**在下一次完整检查点前最多 126 次状态变化保存**。保存还发生在批次创建和确认时，具体时长取决于保存序号、采样周期和确认频率，不能统一按 10 秒推算实际损失窗口。已有面板确认的流量不受此问题影响。

### H5 子问题拆分

| 子问题 | 复核结论 | 修复与必要验证 |
| --- | --- | --- |
| 多条件变为任一匹配 | 结构化自定义规则成立；普通面板规则没有这个缺陷。临时测试同时指定 UDP、443，实际生成两条规则。 | 同一条件内部值可任一命中，不同条件必须同时满足。域名/IP 地址族拆分时复制完整附加条件；sing-box 需要处理域名精确/后缀字段组合的语义。验证 TCP 443 及 UDP 非 443 都不被误拦。 |
| 地理前缀与单 IP | 普通 sing-box 路由把地理前缀当域名；结构化 `ip_cidrs` 缺少格式检查，地理前缀可进入无效网段字段；双核心把 `1.1.1.1` 当域名已复现。 | 统一用 `netip` 分类 IP 和网段。地理前缀必须转换为实际支持的规则集，或在配置验证时明确拒绝；不能静默失效。格式错误进入核心之前拒绝。 |
| IPv6 Reality 回源 | sing-box 用第一个冒号拆分，`[2606:4700::1]:443` 实际变成 `[2606`，已复现。 | 共用回源地址解析器，支持带端口域名、括号 IPv6、不带端口的域名/IP 和端口范围校验。 |
| Xray 缺省回源端口 | 显式 `dest` 域名没有补端口；从 `server_name` 回退时会补 443。开启防盗用时还会改写目标，不能说所有配置都必然启动失败。 | 在生成器入口规范化地址和缺省端口，覆盖显式目标、默认目标及防盗用三条路径。 |
| sing-box 防盗用 | 生成器没有处理 `anti_abuse`，开关不能提供报告描述的保护。 | 实现保护适配，或明确拒绝在该核心上启用不支持的开关；不能继续展示已生效状态。 |
| 防盗用端口竞争 | [端口分配](/root/YZboard/YZ-Agent/internal/kernel/xray/reality_guard.go:189)先探测并关闭、之后才让核心绑定，有时间窗口。同起点并行构建可取同端口；属于条件性竞态，本次未做多节点压力复现。 | 进程内登记预留端口直到成功绑定/退出，覆盖失败回收。仅加进程端口表仍不能消除其他进程抢占，绑定失败需要重选重试或使用已持有监听。 |
| Trojan 修改入参 | [配置生成](/root/YZboard/YZ-Agent/internal/kernel/xray/config.go:374)把 TLS 0 改为 1，已复现。服务原始摘要与核心保存摘要可能分叉，后续重复快照会反复重启。 | 在局部副本上补 TLS，或在进入所有摘要计算之前统一规范化。验证相同配置反复应用不重启，且生成器不改变调用者数据。 |
| 重复拦截标签 | 生成器按规则编号追加出站，未去重；当前 Xray 出站管理会拒绝同名标签。正常面板数据库是否产生重复编号没有在本次验证。 | 编号校验及标签去重，增加重复/零编号配置用例，不把数据库正常约束当生成器的唯一保护。 |
| 地理数据目录全局状态 | [地理库准备](/root/YZboard/YZ-Agent/internal/kernel/xray/xray.go:886)仅扫描普通路由，忽略结构化和原生自定义路由；设置的是进程共用资源目录。`os.Setenv` 本身线程安全，“未加锁的数据竞争”表述不准确，多实例覆盖目录的逻辑竞态仍存在。 | 扫描所有受支持引用。优先确定统一资源目录或按核心构造上下文传递；若使用全局变量，需要覆盖完整设置、解析和使用阶段，单锁一次赋值不够。 |

| M3 | 部分成立 | [热更新](/root/YZboard/YZ-Agent/internal/kernel/xray/xray.go:500)没有内部生命周期锁，认证开放确实先于核心的用户限制映射更新。但 Service 主循环串行更新，且 [外层包装](/root/YZboard/YZ-Agent/internal/directwg/kernel.go:153)对启动、停止、用户修改大多持同一锁；正常路径的风险低于报告所称任意并发重载。集中设备准入开启时，未知用户映射会拒绝，而非绕过设备限制。修复应让底层 API 也满足生命周期一致性，先安装限制再开放认证，失败回滚；重建分支使用锁内辅助方法，避免递归取得同一把锁。需用阻塞模拟及真实连接验证窗口，本次未复现并发覆盖。 |
| M4 | 成立 | [防火墙失败](/root/YZboard/YZ-Agent/internal/service/firewall.go:61)只给开启来源策略的应用错误记录启动重试状态，普通节点同配置可一直停机。全局规则重试不等于服务重新启动。[机器节点创建](/root/YZboard/YZ-Agent/internal/machine/machine.go:350)按配置核心判断是否重建，传输探测仅在首次创建执行。给所有可恢复防火墙失败登记同配置重试；配置变更时重新解析有效核心，明确核心字段未变而传输要求改变时仍重建该节点。 |
| M5 | 部分成立 | [全局防火墙管理](/root/YZboard/YZ-Agent/internal/firewall/manager.go:236)在持锁期间准备工具和调用外部命令，[关闭](/root/YZboard/YZ-Agent/internal/firewall/manager.go:261)先取同一锁再取消，确有阻塞问题。实际软件包安装上限为 [120 秒](/root/YZboard/YZ-Agent/internal/firewall/source_dependencies.go:18)，随后规则阶段另外 30 秒；报告把它描述为“安装最长 150 秒”不准确。正常主入口停机先取消父上下文，对阻塞有缓解。把安装放在管理锁外，基于计划代次提交结果；取消入口应独立于被外部命令占有的锁，并让所有在途应用命令继承管理生命周期。 |
| M6 | 部分成立 | [系统 WG](/root/YZboard/YZ-Agent/internal/systemwg/tunnel_linux.go:95)只根据顶层允许网段安装路由，若它未覆盖各对端网段则缺路由。顶层本来覆盖全部对端时并不失败。[模型验证](/root/YZboard/YZ-Agent/internal/model/relay_validate.go:451)已逐对端验证网段及重叠，不能说完整业务路径没有格式验证。底层独立拼接前仍缺验证。明确顶层与对端网段的语义，从已验证对端合并必要路由，并在底层再次解析后输出，避免文本注入及无效 UAPI。 |
| M7 | 成立，字段丢失已复现 | [配置重写](/root/YZboard/YZ-Agent/internal/agentcli/main.go:1004)采用裁剪结构，内联令牌、独立模式和顶层自定义核心字段丢失；最后绑定清空时没有形成待绑定状态，单实例还会从旧顶层配置重新生成绑定。应复用保留字段的 YAML 修改机制；内联令牌迁移到权限受控的凭据文件并更新引用，不能直接丢弃。最后解绑清除顶层身份并写入 `binding_idle: true`。验证绑定前后未知扩展字段、独立配置和重启等待态。 |
| M8 | 成立 | [机器主循环](/root/YZboard/YZ-Agent/internal/machine/machine.go:238)启动多个后台任务；结束主要等待节点，未统一等待机器控制、地址、发现、WS、流量及发送任务。部分接口使用不继承取消的调用。旧任务可能迟到写入相同状态文件。编排器创建自己的可取消生命周期，所有退出路径取消它，统一登记并等待后台任务；所有请求使用对应可取消版本。新编排器开始前完成旧实例停止屏障。 |
| M9 | 部分成立 | [单节点回调](/root/YZboard/YZ-Agent/internal/controlplane/panel.go:166)没有过滤被替换的旧连接；状态通道满时丢弃。WS 未连接的重试也会重复通知断开。机器模式已有当前连接检查和发现请求合并，不等于每次通知都无限并行请求全部节点。增加连接代次过滤，合并保留最新状态及补同步标记；只在状态迁移时广播，现有定时兜底继续运行。不要仅增加通道容量。 |
| M10 | 部分成立，空闲健康码已复现 | [主程序运行配置](/root/YZboard/YZ-Agent/cmd/yz-agent/binding_deletion.go:11)取首实例，[命令行健康端口读取](/root/YZboard/YZ-Agent/internal/agentcli/main.go:2005)取第一个正端口，规则不一致。[待绑定健康](/root/YZboard/YZ-Agent/cmd/yz-agent/health.go:99)返回 503，安装升级的健康等待可能误判。[隐私重载失败](/root/YZboard/YZ-Agent/cmd/yz-agent/main.go:242)返回到 main，退出码为零，但默认安装器和管理器均写 `Restart=always`，所以“不自动拉起”对默认部署是误报。统一端口解析；可管理的待绑定态返回 200 并保留 `unbound` 状态；不可继续的重载错误返回非零或保留旧有效配置。强制退出清理只能尽力执行，不能引入无限等待。 |
| M11 | 部分成立 | [明文日志创建](/root/YZboard/YZ-Agent/internal/config/config.go:1120)及日志轮转回退使用 0644；ACME 证书目录可用 0755。是否被其他用户读取取决于父目录、文件权限和用户 umask，目录 0755 本身不证明私钥可读。[脚本卸载](/root/YZboard/YZ-Agent/install.sh:1894)和 Go 卸载都未显式调用遗留规则清理，正常停止可清理，但异常停止后卸载会残留。默认私密目录 0700、文件 0600；核对完整创建/轮转路径。卸载在删除程序和状态目录前调用本实例规则清理，失败保留可恢复状态，不能删除其他实例规则。 |

## 四、低危项

| 编号 | 核对结果 | 实际问题与推荐修复 |
| --- | --- | --- |
| L1 | 成立；短窗口的统计一致性问题 | [WG 许可撤销](/root/YZboard/YZ-Agent/internal/directwg/device_handover.go:104)手工清理连接表时少删来源 IP 表。正常转发的关闭回调随后会清理，不能据此说永久泄漏。撤销路径和关闭回调共用幂等清理，同时删除连接、许可和来源映射。 |
| L2 | 成立；“未注册信号”表述需收窄 | [首次时间检查](/root/YZboard/YZ-Agent/internal/timesync/manager.go:157)同步执行，底层 NTP 收发固定 5 秒超时。主入口在此前已注册信号，但等待信号的主 select 尚未运行，所以延迟的是处理，不是信号注册。使首次检查异步但仍保持需校时协议的启动门禁；收发超时及取消应继承配置，跟踪实际交换任务直至结束。 |
| L3 | 部分成立 | [远端能力判断](/root/YZboard/YZ-Agent/internal/agentcli/remote.go:58)通过当前可执行路径及文件身份确认安装来源，磁盘文件替换后可使能力变为不可用。但 [配置周期校验](/root/YZboard/YZ-Agent/internal/config/intervals.go:6)已经拒绝负数和异常退避，且有实际测试，正常路径不会直接收到这些负数。远端重启应基于已核对服务身份及已安装管理入口，不能只删除 `(deleted)` 后缀并信任任意替换文件。构造 WS 客户端时再检查正值属于内部接口加固。 |

## 五、修复前的验证

测试使用当前固定源码和已有依赖缓存，设置依赖只读及离线解析；未安装依赖、未修改源码、未运行安装/升级/卸载流程，未使用真实凭据。追加测试通过 Go 的临时文件覆盖机制运行，实际文件都在本次专用 `/tmp` 目录中。

12 个顶层专项复现测试包含 18 个末端用例。它们断言应有的安全或恢复行为，当前均能产生对应缺陷失败；这不是“测试通过证明已修复”。结果如下：

| 验证 | 当前结果 |
| --- | --- |
| 流量清空 → 新流量 → 新存储对象恢复 | 应恢复 `[30, 40]`，实际 `[0, 0]` |
| 10 秒网速采样；其他用户计数回退 | 有效用户速率均丢失 |
| 双核心结构化 UDP+443 自定义条件 | 各生成两条独立规则 |
| 双核心字面单 IP | 进入域名字段 |
| sing-box IPv6 Reality 回源 | 服务器字段变成 `[2606` |
| Xray Trojan 配置输入 | TLS 从 0 被改为 1 |
| 加密日志尾部部分写入后继续记录 | 连续写入失败，均为 `unexpected EOF` |
| 不同面板归属声明使用已有密文 | 未认证对应归属仍解密成功 |
| 配置重写 | 测试内联令牌及独立模式字段丢失 |
| 错误目标版本；校验清单缺失 | 模拟执行器都在拒绝前被调用，未实际执行下载文件 |
| 待绑定健康 | 返回 503 |
| Xray SOCKS → localhost → 本机回环应答 | 成功访问，应被默认拦截 |
| 面板认证 POST 遇到跨来源 307 | 测试令牌请求体被重发 |
| 特殊设备文件读取 | `/dev/null` 被接受；未读取 `/dev/zero`，未制造内存耗尽 |

另执行了两个独立探针：

1. 在临时目录只提取安装脚本选择函数执行，未运行安装器。无显式本地程序参数时，它选中了同名文件。
2. 临时 Go 进程固定初始线程，为该线程新建网络空间，再让锁定协程退出；另一个宿主空间线程读取路径。文件描述符均可打开，进程网络计数只见隔离空间，当前线程计数可见宿主网卡，证明 C3 应区分描述符可用性和网络空间归属。

对照验证包括已有的待报流量读写/清理测试、双核心普通面板路由条件测试、系统网络空间隔离测试和配置周期负数/溢出验证。按单项输出确认结果；没有把未执行的测试算作通过，没有执行产品全量回归或生产压力测试。

对照结果：系统网络空间隔离测试通过；Xray 路由条件测试通过；sing-box 包中选择的普通路由条件及双核心运行测试通过（35.5 秒）；待报流量已有清理测试通过。周期校验在第一组筛选中未选中用例，随后单独运行 `TestEveryIntervalRejectsNegativeAndOverflowValues` 通过。这说明已有测试可以通过，同时仍缺少本次暴露的异常路径。

尚未动态复现的项，如多节点防盗用端口碰撞、编排器退出并发写、调度器极限并发额度和各云凭据实际权限，结论基于实现和固定依赖追踪，修复时需补针对性的阻塞、并发和端到端用例。

## 六、修复顺序与交付边界

### 第一批：计费和可利用的安全边界

1. C4：纠正检查点状态，补救孤立增量恢复；覆盖重复清空、新增流量、重启及旧损坏状态保护。
2. C1、C2、H1：统一升级校验及参数/本地文件入口；发布签名与程序验证配套落地，保留第三方镜像。
3. H4、H7 中认证传输部分、H3 中读取边界：补齐最终拨号私网策略、认证重定向/WS 降级拒绝、实际字节限制。
4. H2：隔离解密身份及离线缓存归属，验证多面板同机器编号、改绑、凭据轮换、合法离线恢复。

### 第二批：运行功能与配置可靠性

修复 H5 的路由、地址和 Trojan 入参，M2 自动临时限速，M7 配置保存/最后解绑，H6 真实入站健康策略，M1 加密日志恢复。每个独立问题有独立回归；双核心共享逻辑同时验证两个核心。

### 第三批：生命周期、恢复与本机管理

处理 C3 的监控归属、M3–M6、M8–M11 及低危项。并发修复验证取消、迟到结果、重复关闭和失败回滚；卸载验证仅回收当前实例规则。

签名机制不能只改客户端立即发布：现有附件没有签名，必须先建立发布密钥和可信公钥、生成受签名保护且包含版本/附件身份的清单、核对构建发布流程，再启用默认拒绝。签名证明发布来源，不替代版本/回滚策略和发布账户保护。自动最新版本需要防止重放导致错误版本选择；显式历史回滚继续按原项目边界保留。

限制远端私网路由、云默认凭据和证书目录时，需要先明确本机授权策略及兼容迁移。已有本机明确配置的 IAM 或私网通信不能被无条件删除。普通配置缺陷可先修，不必等全部安全策略讨论完成。

以上是首次复核时的结论和建议。实际修复范围以本节下方记录为准。

## 七、本地修复结果

| 编号 | 处理结果 |
| --- | --- |
| C1 | 按本次范围保留现有签名和清单策略。 |

| H3 | 只读普通文件并限制读取字节数。面板证书限于本机证书目录或本机配置的文件对。面板 DNS 禁用自定义接口、宿主凭据文件和未获授权的默认云凭据。 |
| H4 | 双核心在面板管理的直连出站校验实际目标，域名解析后使用通过检查的地址。内网服务需要本机定义的出站及匹配规则。 |
| H5 | 多条件同时匹配，目标组内仍可任选。修正单 IP、重复拦截编号、带端口 IPv6、回源默认端口和 Trojan 配置副作用。Xray 使用进程内统一地理库。防盗用入口串行分配和启动，无法建立时报告错误。 |
| H6、H7 | WireGuard 落地跳过不适用的宿主 TCP 检查。健康地址限本机，禁止面板认证跨来源跳转及 HTTPS 推送降级。限制读取和下载大小，修正调度器会话上限和半关闭排空。 |
| M1、M2 | 隔离加密日志末尾半写文件并续写，支持十秒测速，一个用户计数回退只重置其测速和触发记录。 |
| M3、M4 | Xray 串行更新用户、重载和停机，新增用户先注册限制，失败尝试还原。防火墙失败记录为可重试状态，节点传输要求变化时重新选择核心。 |
| M5、M6 | 安装防火墙依赖期间释放管理锁，同一节点的旧计划不能覆盖新计划或撤回。WireGuard 合并已校验的对端内核路由。 |
| M7、M8 | 按绑定身份保留原配置字段，支持旧内联凭据、独立模式和扩展字段。最后解绑进入待绑定状态。编排器取消并等待后台任务。 |
| M9、M10、M11 | 长连接更换后过滤旧回调，队列满时保留待补同步标记。健康端口由守护进程和管理命令共用解析规则，待绑定返回 200。重载失败退出非零，强退前限时清理。新建日志和证书使用私密权限，卸载时检查本实例防火墙规则。 |
| L1、L2、L3 | WireGuard 撤销时同步清理连接来源，首次 NTP 校时异步运行并受实际超时约束。服务进程可在已安装程序替换后识别管理身份，修正长连接退避边界。 |

使用 Xray 地理库的多个实例若有各自的地理数据目录，需在同一个 Agent 配置中统一 `kernel.geo_data_dir`。多实例未显式指定时使用配置根目录。Xray 原生地理库的匹配缓存与定时重载均为进程级。sing-box 需要将 `geoip:`、`geosite:` 改为规则集或显式域名与网段。需要 Reality 防盗用时选择 Xray。

远端配置 Google Cloud DNS 时使用 `GCE_PROJECT` 和 `GCE_SERVICE_ACCOUNT_JSON`。本机配置可继续指定服务账户文件或使用已配置的默认凭据链。把本机证书对暴露给面板配置时，应使用对应节点的证书目录，或在本机明确指定该证书及私钥路径。
