# 普通 WireGuard 接入

`v2.7.1` 配套面板 `1.53.0`、管理端 `0.30.0`，发布状态见兼容矩阵。普通 WG 使用 `internal/directwg` 管理入口，Xray、sing-box 只负责各自路由和出站；保留已有系统 WG 中转，不修改固定核心依赖。

## 身份与来源

面板配置携带服务端私钥、地址与 MTU，用户列表携带各用户公钥、独立 IPv4/IPv6 地址及到期时间。普通 WG 必须具备完整身份；中转落地继续使用原中转配置。用户密钥、地址、到期变化进入用户同步比较，重复同步保留既有连接，删除或身份轮换关闭旧连接。

WG 完成认证与重放检查后，通过固定 wireguard-go 依赖的 `PeerAwareEndpoint` 回调取得真实外层来源。接收端以单包批次运行，用会话接收编号和包计数器关联认证结果与解密后的报文；不能将任意收到的 UDP 当成用户在线。升级该依赖时必须重新验证数据头保留和认证回调语义。

按外层公网 IP 使用现有设备过滤规则：IPv4 单地址、IPv6 /64、排除名单、35 秒有效的面板全局快照。用户准入在锁内完成，拒绝超额新来源。WG 无断线通知，已准入来源以 90 秒认证活动期限释放；保活只能续期已有来源。在线上报不使用隧道地址。

一个用户在一个节点共享一个 peer；相同身份被多台设备同时使用时，WG 的端点漫游可能互相抢占。设备限制仅限制在线 IP，不提供配置份数管理，也不改变这一协议特性。

## 运行与累计数据

用户态网络栈接收合法隧道地址的 TCP/UDP，交给所选核心。普通 WG 不创建系统网络接口或路由，不提供 ICMP，不使用原中转的 Linux TCP/BBR 路径。

计费在每条 TCP/UDP 转发连接上记录有效负载；握手、保活、IP/TCP/UDP 头和加密开销不计。累计数跟随管理器，删除用户、重载、停止均不清零，沿用服务层差值上报及面板批次去重。共享限速器在各连接内等待，不阻塞所有用户共用的隧道设备；连接数和连接速率使用原限制器。

每包检查用户是否有效，用户到期后停止转发，后台每秒删除到期 peer 并关闭已有连接。封禁、额度耗尽、权限组变化由面板推送或轮询撤销用户。变更监听、来源策略等配置会重建普通 WG 入口，现有会话需要重新握手；失败停止新入口，不把失败配置标成运行中。

大陆来源网段在启动时编译为集合，外层 UDP 接收和发送均检查。具体例外已在来源服务层扣除；缺少首份有效数据时停止节点，见 [来源策略](source-policy.md)。WG 中转落地仍不单独启用来源策略，由前置识别用户来源。

## 验证

测试使用运行时生成的临时密钥、本机回环回显和文档保留网段，覆盖两种核心的 TCP/UDP、用户撤销恢复、密钥轮换、限速、到期、来源拦截、同端口重载及失败恢复。IP 准入还覆盖跨协议快照、IPv6 /64、排除名单和并发额度。

编译需保留 `with_wireguard`、`with_gvisor` 及现有完整功能标签。Linux 构建与 Windows 本地运行测试的结果分开记录在 [兼容矩阵](../YZ_COMPATIBILITY.md)；未进行真实服务器验证。
