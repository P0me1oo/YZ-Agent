# Next 链路诊断

Agent 2.53.0 配套 Next 0.29.0。配置中的 `health_check` 接受面板生成的检查代次、检查目标、请求编号及可选协议客户端。该配置不进入核心重载指纹。

检查每 Agent 最多四轮，每节点一轮，每轮两路并发、四条落地轮转、30 秒期限，DNS 五秒与 HTTPS 八秒共享地址回退预算。检查结果仅保存当前配置、核心运行和证书状态对应的测量；旧任务取消后不能发布。启动失败仍返回可诊断结果，普通停用或缺少可检查路径不伪造健康。

节点监听检查验证进程 TCP／UDP 套接字。真实协议客户端优先使用现有有效授权用户，支持 sing-box 和 Xray（含 XHTTP）以及 WG endpoint。前置自身、各条前置到落地的代理路径、落地自身出站与端口转发分别报告。真实协议探针按现有用户策略与流量规则处理，不创建绕过用户；没有有效客户端时提供核心出站测量和未完成说明。

Next 独立结果上报每节点单飞、整机八路、三秒超时，不阻塞实时状态、配置同步或流量账单。旧面板配置没有检查代次时不使用新上报接口，继续原有 operations 通道，并保持旧格式限制。

Reality 结果分别记录 DNS、连接、TLS 和兼容性检查；保留握手延迟，增加总耗时，失败也提供耗时及原始原因。公网目标检查和不跟随重定向保持生效。

本地验收：双核心×双核心×三种落地协议×VLESS/HY2 入站的完整协议链路、落地停止与恢复、出站失败；Realm 与独立网络空间内 nftables 转发；完整 Next HTTP/WS 和 Agent 子进程的端口占用、DNS 失败、HTTP 失败及重启；竞态检查见 Next `docs/link-diagnostics-acceptance.md`。此版本为本地开发交付，尚未发布或部署。
