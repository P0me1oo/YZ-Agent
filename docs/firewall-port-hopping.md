# 自动防火墙与 Hysteria2 端口跳跃

`v2.22.1` 开启系统来源限制时优先 nftables，缺少工具的 Linux root 主机按需补装；已有规则的后端不直接迁移。普通自动放行和手工模式不触发安装，也不启用 nftables、UFW 或 firewalld 服务。安装范围、超时、失败退避与回退条件见[来源限制](source-policy.md)，正式发布状态见[兼容记录](../YZ_COMPATIBILITY.md)。

## 按节点接管与退出（v2.22.0）

配套面板 `1.101.0`、管理端 `0.72.0`。节点“高级设置 → 连接设置”的“自动管理防火墙”默认开启，配置字段为 `auto_firewall`；旧配置缺少字段也按开启处理，独立模式可在 `standalone.node.auto_firewall` 明确关闭。本机全局 `firewall` 配置仍然优先，程序不自动安装或开启 UFW/firewalld。

开启后该节点的来源限制以面板为准。固定监听端口先安装并回读核验来源过滤，确认核心成功监听后，才通过 UFW 的优先放行或 firewalld 的托管优先级接管端口。原手工规则一直保留，其限制在托管范围内由面板策略替代；其他端口、监听地址、协议和地址族的规则不动。面板关闭来源限制时允许所有来源，仍执行原代理认证、权限、线路和限速。

关闭开关会先停旧监听，撤回该节点的放行、系统来源过滤及跳跃转发，再启动手工模式。原手工规则的位置和内容未改动，会重新生效；来源名单仍保留给核心，但不再保证在握手前拦截，动态 UDP、自定义入站和云安全组的原有限制继续适用。共有规则仅在最后一个使用者退出时回收。开关变化可能中断连接，不重置已有累计。

规则写入、核验或清理失败时不宣称切换成功；撤回失败保持停止并重试。启动恢复中其他节点尚未完成归属确认时，先保留旧保护，发现完成后再撤回。UFW 同范围手工公开放行位于拒绝之后、其他进程规则及 firewalld 最高优先级限制等无法安全处理的情况明确报告，不擅自搬动手工规则。

UFW 注释保留实例和规则摘要，并显示 `node=123` 或排序去重的 `nodes=7,123`。托管优先级写入归属状态版本 4；正常停止、规则完全清理后恢复旧格式。回退旧 Agent 前先完成清理，旧程序不能接收尚未撤回的版本 4 状态。升级先更新面板并关闭需保留手工控制的节点开关，再更新 Agent；旧 Agent 不识别节点开关，保存成功不能证明已经执行。

以下 `v2.21.2` 是本地中间方案记录，已由本节节点级接管替代，未作为正式版本发布。

## UFW 冲突检查与节点标记（v2.21.2 本地未发布）

自动放行会在写入前检查覆盖端口的 `DENY`、`REJECT` 和 `LIMIT`，包括未注明协议、端口范围、指定来源及接口的规则。固定监听端口存在这些限制时，保留手工规则，跳过该范围的自动放行并记录“按现有规则提供服务”；不会因此停止节点，也不宣称端口已自动对外开放。重复检查不反复输出同一提示。

例如先允许一个来源访问 `43222`、再拒绝其余来源时，无需删除白名单或拒绝规则。Agent 会清理本实例覆盖受限端口的旧自动放行，保留其他实例及手工规则；合并范围只拆出受限部分，相邻节点的端口继续自动管理。恢复和重载也沿用这一原则。

来源 IP 过滤仍须先成功安装并回读核验，无权限、缺少工具、规则写入或核验失败仍停止受保护节点。端口跳跃会改写目标端口，不能按普通固定端口的方式直接跳过；跳跃范围或转发目标覆盖手工限制时仍报告冲突，需由管理员调整转发方案，不自动绕过限制。

UFW 自动规则注释显示面板节点 ID，例如 `yz-agent:node=123:<实例标识>:<规则摘要>`；多个节点共用规则时为 `yz-agent:nodes=7,123:<实例标识>:<规则摘要>`，列表按节点 ID 排序并去重。合并端口范围显示参与该范围的节点，HY2 跳跃端口也显示所属节点；独立模式等没有有效面板节点 ID 的配置保留原标记。

注释只用于展示和归属管理，不改变放行范围。升级后原位更新本实例旧注释，重复同步不重复写入；手工规则及其他实例标记保持原样。节点退出、重启或 UFW 停用后，按实际注释和原归属记录清理，不要求管理员手动删除旧规则。回退到只认识旧注释的程序前，应先正常停止新版并确认托管规则已清理。

## 来源 IP 限制（v2.21.0 开发中）

面板开启来源限制后，Agent 在固定监听端口先安装并核验系统过滤，再启动核心。无权限、缺少后端、管理关闭、规则冲突或核验失败均停止对应节点，包括中转落地。详细后端选择、UFW 兼容、恢复周期、PROXY 与动态 UDP 范围见[来源限制](source-policy.md)。该版本尚未发布；下文“没有 UFW/firewalld 时跳过端口放行”仅适用于普通自动放行，不允许开启来源限制的节点绕过系统过滤检查。

## 移除中转来源限制（v2.3.0）

面板 `1.37.0`、Node `v2.3.0`、管理端 `0.18.0` 移除自动来源 IP 白名单、出口核对、手动确认和待确认提示，恢复已有自动端口放行。中转绑定、运行开关和端口跳跃不变。

必须配套更新节点程序：只更新面板不能清理旧节点的来源规则。新版 Node 忽略旧面板来源策略；先建立普通放行，再清理本实例旧来源规则，写入失败保留旧规则并重试。保留旧规则格式读取与清理代码，不认领手工或其他实例规则。没有启用 UFW/firewalld 的环境仍不自动安装或启用防火墙。

上述配套版本已发布，先升级 Node，再更新面板，发布核验见 [兼容矩阵](../YZ_COMPATIBILITY.md)。以下旧版本说明保留为历史记录，不代表新版行为；服务器更新由用户执行。

## 内置中转来源限制（v2.1.0）

配套面板 `1.35.0` 后，绑定前置的 SS/VLESS/WireGuard 落地内部端口仅为已确认的前置出口创建精确 IP 放行。前置每 30 秒读取到各落地目标的系统选路地址，面板将它与经过认证的公网地址回报核对；私网/NAT、缺少回报和自定义出站交由管理员确认，不把订阅地址或 DNS 地址当作出口。该核对不是落地抓包，特殊策略路由或按协议 NAT 须确认实际出口。

IPv4、IPv6 按各自来源创建规则；仅来源改变不重建监听。新来源规则成功添加后才回收旧来源和旧的全开放托管规则。端口共用、外部规则或地址不明返回待确认，不停掉整个节点、不新增全开放规则；已有规则保持原样，因此保留的旧全开放规则不能算作来源限制已经生效。

启动时先等待各实例完成发现及检查，再清理未被使用的旧规则；待确认端口的旧规则继续保留。含来源的状态版本为 2，仍读取旧版本 1；旧名称规则可沿用原归属完成来源替换，全部清理后切换新名称。回滚到仅认识版本 1 的程序前，须先让新版正常退出并完成清理。

旧规则合并相邻端口时，须等范围内节点都完成检查后替换，避免保留的范围从 IPv4 或 IPv6 继续全开放。来源已确认的多个节点可以共同完成恢复，不会互相等待。无法解析端口的 UFW 入站应用规则或复杂范围按待确认处理。

管理页展示节点回报的冲突原因。运行中的绑定落地每 30 秒复核规则，配置未变时新增的冲突也会回报，解除后自动清除提示。自动放行仍只支持已有 UFW/firewalld，不代替云安全组。下文的原有生命周期和手工规则归属继续适用，启动恢复以本节的延迟回收为准。

Node `v1.13-yz.24` 配合面板 `1.13.0` 增加自动端口管理。本功能位于 Node，Xray 与 sing-box 的固定依赖不变。版本发布状态和验证结果以 [兼容矩阵](../YZ_COMPATIBILITY.md) 为准。

## 启动、停用和重载

Linux 主机默认开启自动管理。Node 检查正在运行的 UFW、firewalld，内核成功监听后放行对应 TCP/UDP 端口；面板停用或删除节点、清空普通节点用户、正常退出、启动或重载失败后撤销本进程创建的规则。机器模式通过节点发现同步停用状态，界面的订阅显示开关 `show` 不控制节点运行。

多个节点共用同一个管理器。重复同步不会重复添加规则，同一端口被多个节点使用时，要等最后一个节点停止才撤销放行。范围变化后清理旧范围，只改变跳跃范围不会重建内核监听。管理器每 30 秒恢复缺失规则并重试清理，firewalld 重载后的恢复也使用这个周期。

规则归属保存在配置文件旁的 `firewall/` 目录，权限为目录 `0700`、状态文件 `0600`，其中只有端口和规则标识。写入意图后才执行系统命令。进程异常退出或被 `SIGKILL` 终止时，无法立即执行清理；下一次以同一配置路径启动时先回收遗留规则。修改配置路径或删除状态目录前，应先正常停止 Node。

已有手工放行规则保留，停用节点后这些端口仍可能由手工规则放行。相同端口已存在 UFW 拒绝、限制或另一个 Node 进程的规则时，Node 报告冲突，不覆盖它们。共享引用只覆盖同一 Node 进程；同机多个面板或多个节点应使用 `instances` 或机器模式统一管理。

## 配置

默认无需增加配置。需要指定后端时，在配置文件顶层填写：

```yaml
firewall:
  enabled: true
  backend: auto
  redirect_backend: auto
```

| 字段 | 默认值 | 行为 |
| --- | --- | --- |
| `enabled` | `true` | 同时控制自动放行和跳跃转发；设为 `false` 后清理之前的托管规则，由管理员管理端口 |
| `backend` | `auto` | `auto` 检查 UFW、firewalld；可指定 `ufw`、`firewalld`；`none` 仅关闭放行管理，仍允许跳跃转发 |
| `redirect_backend` | `auto` | 优先使用已安装的 `nft`，没有时使用 `iptables`；也可指定 `nftables` 或 `iptables` |
| `source_backend` | `auto` | 来源过滤；UFW 运行且工具齐全时使用 iptables/ip6tables、restore 和 ipset，否则优先 nft，再尝试 iptables 组合；可固定 `nftables` 或 `iptables` |
| `zone` | 空 | firewalld 自动使用活动区域及默认区域；填写区域名时仅管理该区域 |
| `state_dir` | 配置文件目录下的 `firewall/` | 归属记录目录；相对路径以配置文件目录为基准 |

同一进程中所有实例的最终 `firewall` 配置必须一致。`yz-agent` 修改绑定时保留这些字段。Node 不会自动安装或启用 UFW/firewalld 服务；没有运行中的 UFW/firewalld 时不创建普通放行规则，来源过滤与跳跃转发仍需要相应系统工具。来源过滤工具从 `v2.22.1` 开始按需准备，具体条件见上文。

该功能面向具备系统防火墙权限的 Linux 主机安装。UFW 需要 `ufw`，firewalld 需要 `firewall-cmd` 及可用的系统服务；跳跃需要 `nft`，或所用地址族对应的 `iptables`/`ip6tables` 与 `*-restore`。非 Linux 平台不自动管理防火墙，启用自动跳跃会返回不支持。

Docker 的 `--network=host` 只共享网络，不能单独提供宿主机 UFW 配置、firewalld 服务接口或命令权限。需要托管宿主机防火墙时使用主机安装方式；普通容器部署可设置 `firewall.enabled: false`，由宿主机配置放行和转发。云平台安全组仍由云平台管理。

## 在面板设置端口跳跃

按照 [Hysteria 官方端口跳跃说明](https://v2.hysteria.network/zh/docs/advanced/Port-Hopping/)，服务端仍只监听一个 UDP 端口，其余端口由系统转发到该监听端口。

例如，Hysteria2 节点填写：

| 面板字段 | 示例 | 用途 |
| --- | --- | --- |
| 服务端口 `server_port` | `8443` | 内核实际监听的单个 UDP 端口 |
| 连接端口 `port` | `20000-20100,20300` | 客户端可连接的跳跃端口 |
| 跳跃间隔 `protocol_settings.hop_interval` | `5` | 客户端固定间隔，单位秒，设置时必须至少 5 秒；留空使用客户端默认值 |

连接端口支持单端口列表、连续范围及其组合。面板和 Node 校验 `1..65535`、空项和倒序范围，并合并重复、相邻或重叠的范围。面板通过 `port_hopping` 下发跳跃端口，保留单独的 `server_port`；Mihomo 和 URI 订阅保留端口集合，sing-box 订阅转换为合法的多个 `server_ports` 范围。

本轮沿用固定间隔字段，没有新增官方客户端的随机间隔配置。纯单端口连接配置保持原语义，不自动推断外部端口映射。

独立模式在原有节点配置中加入：

```yaml
standalone:
  enabled: true
  node:
    protocol: hysteria
    version: 2
    listen_ip: "::"
    server_port: 8443
    port_hopping: "20000-20100,20300"
```

以上仅展示端口字段，独立模式仍需配置自己的测试或运行身份和证书。

普通 HY2 节点和 HY2 中转入口可使用跳跃，内部落地节点不创建跳跃转发。`listen_ip` 为 `::` 或为空时按双栈管理，`0.0.0.0` 只管理 IPv4，指定地址时只管理该地址。跳跃范围不能把同一 UDP 端口转发到不同节点，也不能覆盖本进程另一个 UDP 节点的真实监听端口。

## 规则实现和范围

UFW 使用带 `yz-agent:` 注释的独立放行规则。firewalld 使用独立优先级的运行时 rich rule 及归属记录，不执行全局重载或修改永久配置。nftables 使用单独的 `inet yz_agent_<标识>` 表，iptables 使用单独的 `YZ_AGENT_<标识>` 链；更新和退出只操作本实例规则。

从旧版升级时，先按归属记录清理 `yzboard-node:`、`yz_node_` 和 `YZH_` 旧规则，成功后再切换新名称；清理失败保留记录供重启重试。默认配置目录搬迁后继续使用原实例标识，避免遗漏旧规则；已有手工规则和其他实例的规则保持原归属。

跳跃只匹配发往本机的 UDP 流量，真实监听端口从转发集合中排除。通配监听使用 REDIRECT，指定地址使用 DNAT。进入本机的流量适用这些规则；本机客户端应直接连接真实监听端口。

自动放行覆盖面板或独立模式定义的主监听，以及中转落地实际监听端口。自定义核心配置额外增加的入站不在自动计算范围内。sing-box SOCKS 的 UDP 会话端口动态分配，自动管理只覆盖它的固定 TCP 监听。

## 验证和升级

原生命令验证使用专用 rootfs、私有挂载/进程/网络命名空间和独立客户端，覆盖 UFW/firewalld 与 nftables/iptables 组合。完整 Node 验证使用临时面板接口、临时身份、自签名证书和官方 Hysteria 客户端，检查真实换端口传输、面板停用、重载错误、状态及流量回传。

复测需要在专用 rootfs 安装相应防火墙工具、iproute2、D-Bus 和 Python，在根目录创建 `.yz-firewall-test-rootfs` 标记。将防火墙 Go 测试二进制放入 `/work/firewall-linux.test`；完整测试还需要 `/work/yz-agent-linux-amd64`、`/work/hysteria-linux-amd64` 和 `scripts/test-firewall-node.py`。测试入口拒绝使用 `/` 或没有标记的目录。

```bash
# 参数依次为专用 rootfs、运行的防火墙、转发工具、测试类型、内核。
sh scripts/test-firewall-linux.sh /path/to/test-rootfs ufw nftables backend
sh scripts/test-firewall-linux.sh /path/to/test-rootfs firewalld iptables node singbox
```

测试实例和身份放在私有 `/run` 内，退出后清理；可复用程序文件，但不能复用测试身份。实际结果、工具版本和限制见 [验证记录](firewall-validation.md)。

本次来源限制的升级顺序为面板、前置、落地；更新落地前先等待前置出口回报并处理待确认来源。旧程序正常停止会清理自己的托管规则，新版无法保留已经清理的规则。旧版端口跳跃功能的升级顺序为 Node、面板、客户端订阅。回滚到没有自动管理的 Node 前，先为旧版准备必要的手工放行/转发，或将 HY2 连接端口改回真实单端口并刷新订阅；正常停止新版完成规则回收后再替换程序。
