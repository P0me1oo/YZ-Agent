# 中转连接的真实来源 IP

节点级“接收 PROXY 协议”开关已随 Agent `v2.16.1`、面板 `1.92.0` 和管理端 `0.64.0` 发布。Agent `v2.21.1`、面板 `1.100.1` 和管理端 `0.71.1` 的本地修复进一步统一开关行为，尚未发布。继续使用原有固定核心依赖，不修改核心 fork。

## 节点接收开关

- 在节点编辑页开启后，自动识别任意来源的 TCP PROXY v1/v2，无需填写中转 IP；不带头的普通连接仍可使用。
- 开启会信任来源声明，必须配合防火墙限制节点入口。关闭不解析任何来源的 PROXY 头，即使旧传输选项仍开启或地址在前置名单内。
- 新建默认关闭。面板把旧节点空值按原界面显示转换为布尔值：旧传输接收选项为 `true` 时开启，其余关闭；已有明确开关不变。独立 YAML 的 `node.accept_proxy_protocol` 未填写且没有旧接收选项时也默认关闭。
- “前置服务器 IP”只影响设备数和相关来源统计，名单变化不改变接收策略。节点级设置优先于 `networkSettings.acceptProxyProtocol` 旧字段；缺少节点级字段时，旧字段恢复为同样的布尔开关，不再按名单决定信任范围。
- 开关变化通过配置推送或轮询触发所属实例重载；重复配置不会重复重建。重载失败沿用既有停止保护，修正配置后恢复；停止后启动沿用当前配置，各节点相互隔离。

升级此修复需同时更新面板和 Agent，先面板后 Agent，两端完成后再操作开关。原来只填前置名单、界面显示关闭却使用带头转发的旧节点，修复后需要明确开启；显示开启的旧节点不再限制为名单内来源。

## 使用方式

客户端正常使用 SS、SS2022 等协议连接 Realm。Realm 不要求客户端提供 PROXY 头，而是在连接落地时附加真实来源：

```json
{
  "accept_proxy": false,
  "send_proxy": true,
  "send_proxy_version": 2
}
```

在实际接收 Realm 连接的节点开启接收即可，无需在“前置服务器 IP”填写 Realm 出口来启用协议。

`realm-xwPF` 脚本的全局开启会同时开启发送与接收。普通客户端应关闭脚本的全局开关，再对相应规则选择“v2 → 仅发送”。若 Realm 放在面板自带中转的 VLESS TCP 入口前，入口开启接收即可；内部落地不要求开启接收，入口仍按真实用户和线路统计一次。原生 HY2/QUIC 的 UDP 入口和 WireGuard 不适用这项 TCP 接收能力。

开启后解析的用户地址进入来源拦截、在线 IP、设备限制及访问记录；不带头的普通连接仍正常处理。关闭时所有来源都不解析协议头。原有统计排除规则继续生效，不从旧连接记录推算用户地址。

统计排除名单属于单个核心实例，更新不重启监听器，也不改写连接来源。完整重载和停止后启动继续使用该实例的接收开关。

## 支持边界

- 作用于使用 sing-box 通用 TCP 监听的入站，在协议认证和 TLS 握手前解析；本地实连覆盖普通 SS、SS2022 AES-128/AES-256、VLESS 和 Trojan。
- TCP 协议头检测最多等待 5 秒；检测在独立连接协程内进行，慢连接不会阻塞其他连接接入。
- 原生 UDP、QUIC 和由其他组件自行创建监听的协议没有增加 PROXY 头解析。不能据此认为 SS 的原生 UDP 已保留真实来源；普通 UDP 转发方式保持不变。
- 用户看到的仍是来源公网 IP，不能依靠该功能识别同一 NAT 后面的具体终端。

验收使用本机回环、运行时生成的测试身份和模拟 Realm 转发器，检查真实地址、开关优先级、名单与接收互不影响、实例隔离、重启与重载、来源拦截，以及业务流量中不包含 PROXY 头字节。没有操作生产服务。
