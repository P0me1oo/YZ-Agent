# 中转连接的真实来源 IP

节点级“接收 PROXY 协议”开关已随 Agent `v2.16.1`、面板 `1.92.0` 和管理端 `0.64.0` 发布。先更新面板，再更新 Agent，两端更新完成后再操作开关。继续使用原有固定核心依赖，不修改核心 fork。

## 节点接收开关

- 在节点编辑页开启后，自动识别任意来源的 TCP PROXY v1/v2，无需填写中转 IP；不带头的普通连接仍可使用。
- 开启会信任来源声明，必须配合防火墙限制节点入口。关闭不解析任何来源的 PROXY 头，即使旧传输选项仍开启或地址在前置名单内。
- 新建默认关闭。旧节点未操作开关时保留未设置状态，并继续使用下文名单策略，不自动扩大信任范围。独立 YAML 的 `node.accept_proxy_protocol` 同样区分未填写、`true` 和 `false`。
- “前置服务器 IP”继续只影响设备数和相关来源统计；明确设置开关后，名单变化不改变接收策略。节点级设置优先于 `networkSettings.acceptProxyProtocol` 旧字段。
- 开关变化通过配置推送或轮询触发所属实例重载；重复配置不会重复重建。重载失败沿用既有停止保护，修正配置后恢复；停止后启动沿用当前配置，各节点相互隔离。

以下名单用法适用于未设置新开关的旧配置。Node `v2.15.0` 已为 sing-box 提供该能力，固定使用 YZ-sing-box `v1.15.0`。

## 使用方式

客户端正常使用 SS、SS2022 等协议连接 Realm。Realm 不要求客户端提供 PROXY 头，而是在连接落地时附加真实来源：

```json
{
  "accept_proxy": false,
  "send_proxy": true,
  "send_proxy_version": 2
}
```

使用新开关时直接开启接收即可；继续使用旧名单策略时，在面板“节点配置”的“前置服务器 IP”中填写 Realm **实际连接落地时的出口地址**。使用独立地址或必要的最小网段。

`realm-xwPF` 脚本的全局开启会同时开启发送与接收。普通客户端应关闭脚本的全局开关，再对相应规则选择“v2 → 仅发送”。若 Realm 放在面板自带中转的 VLESS TCP 入口前，入口开启接收即可；内部落地不要求开启接收，入口仍按真实用户和线路统计一次。原生 HY2/QUIC 的 UDP 入口和 WireGuard 不适用这项 TCP 接收能力。

Node 沿用已有名单下发方式。名单内来源可以携带 PROXY v1/v2，解析后的用户地址进入来源拦截、在线 IP、设备限制及访问记录；不带头的普通连接仍正常处理。名单外来源和空名单不解析协议头，也不能通过开启旧接收选项扩大信任范围。原有转发机地址排除规则继续生效，不从旧连接记录推算用户地址。

名单属于单个核心实例，更新时影响后续接入，不重启监听器、不改写已建立连接的来源。完整重载和停止后启动继续使用该实例的当前名单。

## 支持边界

- 作用于使用 sing-box 通用 TCP 监听的入站，在协议认证和 TLS 握手前解析；本地实连覆盖普通 SS、SS2022 AES-128/AES-256、VLESS 和 Trojan。
- TCP 协议头检测最多等待 5 秒；检测在独立连接协程内进行，慢连接不会阻塞其他连接接入。
- 原生 UDP、QUIC 和由其他组件自行创建监听的协议没有增加 PROXY 头解析。不能据此认为 SS 的原生 UDP 已保留真实来源；普通 UDP 转发方式保持不变。
- 用户看到的仍是来源公网 IP，不能依靠该功能识别同一 NAT 后面的具体终端。
