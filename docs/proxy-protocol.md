# 中转连接的真实来源 IP

Node `v2.15.0` 为 sing-box 增加 TCP PROXY protocol v1/v2 接收能力，固定使用 YZ-sing-box `v1.15.0` 的兼容补丁。已有“前置服务器 IP”设置同时决定可信来源，无需增加新的面板字段。

## 使用方式

客户端正常使用 SS、SS2022 等协议连接 Realm。Realm 不要求客户端提供 PROXY 头，而是在连接落地时附加真实来源：

```json
{
  "accept_proxy": false,
  "send_proxy": true,
  "send_proxy_version": 2
}
```

在面板“节点配置”的“前置服务器 IP”中填写 Realm **实际连接落地时的出口地址**，不能直接把 NAT 内网地址或面板中的节点地址当作出口地址。使用独立地址或必要的最小网段。

Node 沿用已有名单下发方式。名单内来源可以携带 PROXY v1/v2，解析后的用户地址进入来源拦截、在线 IP、设备限制及访问记录；不带头的普通连接仍正常处理。名单外来源和空名单不解析协议头，也不能通过开启旧接收选项扩大信任范围。原有转发机地址排除规则继续生效，不从旧连接记录推算用户地址。

名单属于单个核心实例，更新时影响后续接入，不重启监听器、不改写已建立连接的来源。完整重载和停止后启动继续使用该实例的当前名单。

## 支持边界

- 作用于使用 sing-box 通用 TCP 监听的入站，在协议认证和 TLS 握手前解析；本地实连覆盖普通 SS、SS2022 AES-128/AES-256、VLESS 和 Trojan。
- TCP 协议头检测最多等待 5 秒；检测在独立连接协程内进行，慢连接不会阻塞其他连接接入。
- 原生 UDP、QUIC 和由其他组件自行创建监听的协议没有增加 PROXY 头解析。不能据此认为 SS 的原生 UDP 已保留真实来源；普通 UDP 转发方式保持不变。
- 用户看到的仍是来源公网 IP，不能依靠该功能识别同一 NAT 后面的具体终端。

验收使用本机回环、运行时生成的测试身份和模拟 Realm 转发器，检查真实地址、未受信来源、名单热更新、实例隔离、重启与重载、来源拦截，以及业务流量中不包含 PROXY 头字节。没有操作生产服务。
