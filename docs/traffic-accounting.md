# 用户流量计量与权限撤销

维护者：P0me1oo。版本：`v2.38.0`，最终发布准备。

## 统计范围

用户流量统计代理连接读取和成功写入的有效负载，保持上传、下载两个方向分别累计。握手、保活和外层隧道开销不纳入用户套餐；服务器网卡流量采用独立统计口径。

中转入口统计用户套餐流量，并独立记录逻辑落地节点及用户在各线路上的用量；中转落地不重复扣除用户套餐。普通 WireGuard 的用户认证、准入及流量由 Agent 的外层入口处理。

## 修复后的行为

### 已撤销的旧会话

从节点用户列表移除用户，或轮换连接凭据后，sing-box 普通节点也会拒绝旧 Hysteria2、TUIC 会话发起的新 TCP/UDP 请求。已建立的普通代理连接仍使用原用户计数，权限变化不能使它们变成不计费连接。

普通 WireGuard 和私有中转落地可以通过没有面板用户名称的内部路由；其认证仍由外层 WireGuard 或落地入站执行。普通用户入站不会把未知身份当作内部连接。

### DNS 接管

启用原生 `hijack-dns` 路由规则时，Agent 将规则的处理目标接入自己的 DNS 出站适配器，沿用核心现有 DNS 解析组件及规则条件、优先级和缓存。请求及响应经过已有用户流量、连接、设备准入和限速处理，不再在进入统计器前返回。

适配只改变生成的运行配置，不改写面板持有的规则，不覆盖用户自定义出站标签。没有 DNS 接管规则时不增加 DNS 出站；重复配置生成和重载不会重复添加。

DNS 的普通 UDP 读取路径保留用户计数包装，避免核心在读取回退时重复调用计数回调。缓存应答仍是已经向用户发送的流量，照常计数。

### WireGuard 成功写入与撤权交错

下载写入前继续检查当前用户、到期时间及限速。写入成功后，仅按实际成功字节数结算，用户删除、密钥轮换、到期或账本回收不能取消已完成写入的计数。TCP 部分写入只计成功前缀；UDP 写入失败不计下载。

### 协议切换和历史账本

同一节点进程内在普通代理协议与普通 WireGuard 之间切换，用户累计由核心账本和 WireGuard 账本相加，在线来源和连接数仍取当前协议。停止、重载及重复读取不会隐藏旧协议尚未采集的流量。

历史账本按合并后的已确认基线回收；两份账本中任一仍活跃或出现新增字节时保留原累计。回收后的迟到成功写入只形成新增量，避免部分回收导致采样基线回退和重复计费。

## 最终固定版本验证

正式依赖已固定至 YZ-sing-box v1.16.0 和 YZ-Xray-core v26.12.0。整仓竞态回归 41 包、1018 个顶层用例通过，6 个既有原生网络/端口环境用例跳过；8 包依赖竞态及 10 份安装器检查通过。来源及源码摘要见[核验记录](traffic-accounting-verification.json)。以下保留开发阶段的原始测试范围。

## 开发阶段验证

使用 Go `1.27.3`、Linux amd64 和正式功能标签，C 编译器为任务临时目录中校验过的 Zig `0.14.1`。未安装系统软件或改动服务。

修复前回放测试确认旧 QUIC 会话撤权后仍能新建请求、DNS 接管漏计、成功下载在撤权交错时丢失，以及协议账本未合并。修复后专项并发测试通过，覆盖：

- Hysteria2/TUIC 用户删除、凭据轮换后的旧会话新 TCP/UDP 请求拒绝；原连接继续计数，其他用户保持可用。
- VLESS/XUDP 和 Shadowsocks 原生 UDP、TCP 的 DNS 请求及缓存应答精确累计，重复重载和读取不重复计数；DNS 会话进入连接和来源统计。
- DNS 规则顺序、逻辑条件、出站标签冲突、原配置不被改写及生成配置解析。
- WireGuard TCP 部分写入、UDP 成功/失败、撤权前拒绝、删除、轮换、到期和回收交错。
- 两份账本合并、未确认保护、活跃和新增字节保护、迟到写入、4,000 次并发下载及两种核心的实际协议切换。

受影响的 9 包完整竞态回归中，554 个顶层用例通过，无断言失败或数据竞争；3 个既有环境用例跳过。Linux amd64、arm64 验证构建通过，构建来源是未提交工作区。静态检查仍有 Xray 基线文件中的取消函数路径告警。完整范围及限制见 [兼容矩阵](../YZ_COMPATIBILITY.md)，源码摘要和构建校验值见 [核验记录](traffic-accounting-verification.json)。

验证采用正式 `go.mod`、`go.sum` 中的固定核心，不引用本地核心，不修改面板通信格式。没有执行生产部署或生产流量核验；历史遗漏流量无法由本次源码修复追回。
