维护者：P0me1oo。日期：2026-11-16。状态：本地开发，未发布。

适用候选版本：YZ-Agent `v2.38.0`、YZ-sing-box `v1.16.0`、YZ-Xray-core `v26.12.0`。正确性、竞态与构建结果见 [DHT 验证记录](dht-validation.md)。

## 测量方法

环境：Linux amd64、AMD Ryzen 9 9950X、Go 1.27.3、`CGO_ENABLED=0`。同一组基准前后各执行 3 次，单 CPU，单次 300 ms；下表取中位数。基准顺序执行，不同时测量不同实现。优化前通过临时 Go 覆盖文件还原本次开始时的解析器、UDP 检查器与匹配代码；规则配置和负载保持一致。

这些是函数级 CPU 和分配结果，不包含网络收发、加密、数据库或面板上报，不能直接换算为生产吞吐提升比例。普通 UDP 非 `d` 前缀仍只需数纳秒且不分配；优化重点是候选报文和 DHT 的处理成本。

## 网络和连接开销

- 恢复带过滤的单包、批量和同目标批量读取，所有缓存报文也通过检查；写入使用原底层快速路径。测试覆盖混合批次、每包目标、空批次、部分错误、缓存耗尽、协议头预留和禁止读取解包绕过检查。
- Xray 首包嗅探借用已缓存报文，并在嗅探期间持有缓存锁保护生命周期，取消每次 UDP 嗅探额外申请的 128 KiB 缓冲和复制。QUIC 的汇集输入保持原行为。
- 不增加探测报文、报文头或额外转发。DNS 仍按原路由策略、缓存有效期和禁缓存选项执行；不额外缓存路由结论，不绕过明确关闭缓存的配置。域名条件重新匹配时仍可能调用 DNS 查询。
- 首包和后续 DHT 都按实际规则丢弃，普通 UDP 可以继续使用同一 XUDP 会话；日志仍按同会话、目标及规则去重。

## 复现

在 YZ-sing-box 根目录执行，确保使用 Go 1.27.3：

```bash
go test -mod=readonly -run '^$' \
  -bench '^(BenchmarkIsMessage|BenchmarkDHTGuard)$' \
  -benchmem -benchtime=300ms -count=3 -cpu=1 \
  -tags 'with_quic with_utls with_wireguard with_acme with_clash_api' \
  ./common/dht ./route
```

不使用 `-race` 测量性能；竞态检查单独执行。再次比较时应保持编译器、运行环境、规则和负载一致。正式依赖与版本常量未切换，本记录不代表已发布或已部署。
