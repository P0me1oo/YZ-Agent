# 三机隔离性能对照

本工具只为本次实验使用，不读取或更改已有 Agent 实例，不安装系统服务。

## 拓扑和负载

- Ciallo-HK：只运行被比较的前置程序。
- Panstar-HKL：每轮仅运行该方案的落地入站、临时 REALITY 握手目标和 HTTPS 数据目标。
- KZC-HK Lite：运行独立客户端。所有业务测试流量从该服务器产生，本地电脑只做控制和读取结果。

三机均为单核 x86_64。目前 Ciallo-HK 内存约 2GB，另两台约 1GB；须记录客户端、前置和落地 CPU，避免把客户端或落地先跑满当成中转上限。

使用 TCP 28101–28106；不占用 443。28101 是各方案共用的前置端口，28102 为普通 Reality 落地，28103/28104 为旧 SS2022/VLESS 内部落地，28105 为临时握手目标，28106 只监听落地回环地址提供 HTTPS 数据。启动前重新检查端口，端口被占用时停止本次启动，不接管原服务。

比较五组：新 shortId 入口的 splice、同入口强制 buffered、原版 Realm TCP 透传、现有 sing-box 入口到 SS2022，以及现有 sing-box 入口到 VLESS+Reality+Vision。后四种 Go 路径使用同一测试外壳和固定核心；Realm 使用与本地源码一致的 v2.9.6 官方附件。所有客户端均使用相同的 Reality/Vision、SNI、入口端口和线路身份。

先做每组 1MiB 的上传及下载连通检查。最初每组分别上传、下载单连接各 64MiB、四并发各 128MiB、小请求各 8MiB；完成七组后因时间上限停止，其中旧 VLESS 链式方案有一次短连接下载不完整，保留失败记录，没有重跑该项。

用户随后取消总流量上限。为获得更完整的 CPU 采样，另执行三次交错重复：每组每次分别上传、下载单连接各 512MiB、四并发各 512MiB、128 个新连接的小请求各 8MiB（每个 64KiB、并发一）。最终系列每组总量 2064MiB，15 组共 30.23GiB；含此前检查和测量，累计请求预算约 32.98GiB。它跨两段线路，不等于三台账单流量合计。最终窗口最长 30 分钟，单轮最长 130 秒；到期结束本次进程，错误请求计入累计预算，失败项不自动重试。

顺序为第一轮 new、old-ss、realm、old-vless、buffered，第二轮 buffered、old-vless、realm、old-ss、new，第三轮 realm、new、old-vless、buffered、old-ss。各方案按相同负载次序执行，每轮间留出恢复时间。

客户端结果只统计完整收到或得到服务端确认的有效载荷；任一请求失败，该轮不作为成功吞吐。连接数按实际新连接计，连接建立耗时包括 Reality、代理和目标 HTTPS 握手，另记录首字节及完整请求的中位数和 95 分位数。它们是端到端耗时，不能直接解释为前置单独增加的耗时。

Go 程序统一同一构建、固定核心、单核执行和 192MiB 的 Go 内存软上限。Realm 使用核验过的官方 Rust 构建，无法声称与 Go 使用同一编译器。记录三台 CPU 时间、RSS、主机忙碌/steal 和换页。前置、落地每 0.2 秒采样，按客户端开始和结束时间对累计计数插值；客户端使用系统逐进程累计 CPU 时间和最大 RSS，包含启动和退出。早期系列的客户端最大 RSS 是该 Python 管理进程此前子进程的累计峰值，最终系列已改为逐进程 wait4；不能把早期的峰值用于精确对照。吞吐撞上线路、客户端或落地瓶颈时，只报告该条件下的资源差异和吞吐下限。

## 程序

`cmd/yz-relay-perf` 构建为 Linux 单文件测试程序，使用当前项目真实内核包装器和新中转模块。`init` 生成一次性前置、落地和客户端配置：客户端不含 Reality 私钥或内部链路凭据，证书和身份仅在运行时生成，禁止打印配置内容。

生成角色文件、启动和清理均限于本次确认的独立目录。服务器上的写入及进程操作在具体测试范围确认后执行；不覆盖已有程序、配置或防火墙规则。测试结束删除一次性身份、私钥、配置和敏感日志，按约定保留或删除不含身份的程序与结果。

`monitor.py` 只读取明确指定测试 PID 的 CPU 时间、常驻内存、线程数和主机 CPU/steal，不读取进程命令行、环境变量或配置；校验可执行文件和进程开始时间，避免采样复用后的 PID。采样输出以独占方式创建，不覆盖已有文件。

`run.py` 仅在服务器本地管理 `/tmp/yz-relay-perf-20261020` 内的测试进程，启动前检查 28101–28108，按程序路径和 PID 开始时间停止进程，保留私有错误文件但不输出内容。总时间到期看护进程会结束本次监听；控制连接中断后仍有上限。它不提供远程连接或防火墙管理。

`firewall.py` 仅在另行授权后添加两条临时规则：前置仅允许独立客户端访问 TCP 28101，落地仅允许前置访问 TCP 28102–28105。每轮生成独立归属标识并写入规则注释，看护只撤销自己所属轮次；增删操作持锁，旧看护不会删除新一轮标记或规则。按完整规则匹配删除，不持久化；看护启动失败会撤销本轮规则，到期自动撤销。本次规则已撤销。

`export.py` 只导出测量结果和进程采样，不导出身份、配置或错误文件。`summarize.py` 在本地读取脱敏结果，计算有效速度、累计 CPU 时间、RSS 和连接耗时，保留原始测量及失败项。

服务器操作已获本次明确授权，仅涉及测试程序、脚本、临时角色配置及上述两条规则。结束后已停止本次程序和采样、核对端口释放、下载不含身份的结果，并删除三台服务器的整个隔离目录，没有保留服务器程序。已有 Agent、系统服务、路由及生产配置未修改。结果和限制见 [实测报告](../../docs/reality-relay-performance-20261021.md)。
